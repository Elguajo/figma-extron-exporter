## Незавершённая диагностика GCP

Ожидается: после Import Layout собранного v1 видны экран и элементы, можно назначать действия. Наблюдалось: список страниц содержит `screen_Home`, но preview пустой (сначала шахматный, после переключения представлений — чёрный). Элементы для назначения недоступны.

Сохранён отдельный свежий тестовый проект `actual-import-diagnostic.gcplus`: IPL Pro CR88 + TLP Pro 1025M, импорт реального v1, **новые действия/feedback/связь регулятора не настроены**. Сохранение и повторное открытие этого проекта не устранили проблему. Переключение System Settings → User Interfaces и Fit To Page также не помогло.

### Что уже проверяли

1. **Цвет текста null — не подтверждённая причина.** В compiled `layout.json` у трёх feedbackbutton TextColor = null, но такое же значение есть у рабочей кнопки предыдущего контрольного макета. На основании одного null ничего не исправлять.
2. **Рабочий предыдущий макет в той же сессии отображается.** Открыта копия предыдущего синтетического GCP-проекта, preview и Press → Relay 1 Toggle видны. Следовательно, пустота не воспроизводится на всех макетах этой сессии.
3. **Прямое редактирование compiled ZIP не дало пригодного эксперимента.** Файлы `diagnostic-no-slider.gdl` и `diagnostic-no-slider-metadata.gdl` получены перепаковкой с удалением PBSlider только из compiled layout. GCP отклонил оба: `Invalid size or check sum of file or unsupported compression format`. Не использовать их как доказательство причины, рабочие макеты или исправление. `ProjectGCP` и compiled данные в этих копиях намеренно расходятся.
4. **Штатный контроль без slider:** из копии EXUI удалён только slider, выполнены convert-package (**143/143**) и GUI Designer → Save and Build → Keep. `diagnostic-source-no-slider.gdl` содержит `.tgz4`, размер 2368265, SHA-256 `6B8FD3912E331F386AC28BF59838C6C517D152054352EB753B2642AD5F7227F3`. После попытки импорта preview оставался пустым. Для строгой изоляции стоит повторить этот импорт в сохранённой чистой диагностической копии: в последних попытках использовалась также копия старого настроенного проекта, были Layout Reconciliation и несохранённые изменения.
5. **Следующий подготовленный контроль без часов:** `diagnostic-source-no-clock.exui` и `.gdl`; удалён только datetime, slider сохранён. Конвертация **144/144**. GDL открыт в GUI Designer. Попытка запуска Save and Build остановлена физическим Escape пользователя. **Сборка ещё не выполнена:** на момент записи этого файла в GDL только `ProjectGCP`, без `.tgz4`; SHA-256 `0E310C33700A8EF2E5BFB5BC7EA0D7424FA4B4102E4C61BCD32605EB14B4DF5D`. Импортировать его для сравнения только ПОСЛЕ штатного Build.

Compiled layout и PNG можно читать из второй записи `.tgz4` (внутри обычный ZIP). Извлечённые `layout.json` для реального v1 и старого рабочего v1 лежат в подпапках `live-1025m-v1-build/` и `../gcp-retry-2026-10-23/tlp-pro-1025m-v1-build/`. Шрифты не распространять.

**`live-configured-v1.gcplus` НЕ является настроенным реальным v1.** Изначально это Save As старого синтетического настроенного проекта. На диске осталась эта копия (размер 2471584; SHA-256 `E83E5C518C42B4B02F52C2978333DC8591FD45E0B37FAF8612C7938574971EEA`). Позже в неё в памяти пытались импортировать реальный v1 и контроль без slider; последние изменения не сохранены.

## С чего продолжать после команды пользователя

1. Осмотреть актуальные окна заново; состояние ниже — только последнее наблюдение. Не использовать старые handles, screenshot IDs и индексы UI.
2. Закончить **Save and Build → Keep** для `diagnostic-source-no-clock.gdl`; убедиться в наличии `.tgz4`. Импортировать в отдельную копию свежего диагностического GCP-проекта и проверить отображение. Сравнить с исходным v1 и штатным контролем без slider. При необходимости уменьшать состав по одному фактору, сохраняя валидную штатную сборку. Не объявлять datetime причиной до результата.
3. Установить минимальный воспроизводимый дефект. Проверить различия в данных/типах/состояниях и поведение GCP. Исправить экспортёр только при доказанной причине; добавить нужную регрессионную проверку и повторить исходное воспроизведение. Не подменять решение удалением поддерживаемого элемента из пользовательского дизайна.
4. Когда исходный реальный экран доступен в GCP, настроить с нуля Music 8102 (Press и Visual Feedback), Mute 8103 (отдельное действие) и регулятор 8105. Для автономной проверки регулятора можно исследовать встроенный Touchpanels → Volume / Master; возможность и конкретная привязка ещё не проверены. При необходимости включить числовое значение 8107.
5. Сохранить `actual-configured-v1.gcplus`, сделать Save As `actual-configured-v2.gcplus`, импортировать реальный v2 с **keep existing layout configuration**. Проверить Music, регулятор, значение; Extra должна быть без чужих действий, Mute — Missing. Сохранить и повторно открыть, снова проверить назначения.
6. Затем отдельно выполнить обновление профиля **300M**, сценарии **страниц/popup**, переименования и изменения структуры состояний/типа. Это будущие проверки, не выполненные в этом прогоне.
7. Записать итоговый протокол и актуализировать документацию по доказанным результатам. Проверка исполнения на физической панели/контроллере остаётся отдельным этапом при наличии оборудования.
