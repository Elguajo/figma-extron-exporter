# Выпуск: плагин 0.8.0 + CLI 0.8.0

24.10.2026. Решение: **SHIP WITH KNOWN RISKS**, preview. Архивы собраны из чистого коммита `08dcd9a13931d0481a5795a0cad57539733ae99a`, в CLI `version.json` записано `sourceDirty: false`. Работа велась непосредственно в `main`, без веток и worktree. GitHub-публикация не выполнялась.

## Изменения

- **Extron Kit.** Apple-inspired Light, AV-сценарии, иконки Lucide, Normal / Pressed для Volume и навигации; нумерация только выделенных кнопок. Всё это вошло в рабочее дерево после 0.7.3 и описано в [CHANGELOG](../../CHANGELOG.md).
- **Совместимость Extron.** Профили `compatibility/extron.json` с параметром `--compatibility` и команда `doctor`.
- **Стабильность и производительность плагина** по [анализу](../../docs/performance-stability-review-2026-10-24.md):
  - P1 — проверочные захваты не строят подпись дизайна;
  - P2 — после выгрузки панель обновляется по применённому плану;
  - область экспорта определяется один раз за событие;
  - S1 — защита событий холста;
  - S4 — события холста во время операций обрабатываются после них;
  - временные копии экспорта PNG помечаются и удаляются при следующем запуске;
  - кнопка «Скопировать диагностику».
- **Стабильность и производительность CLI:**
  - S2 — удаление временных папок без ошибки;
  - S3 — повреждённый ответ хоста и гонка при таймауте;
  - P4 — индекс шрифтов донора в хосте;
  - удаление собственных рабочих папок в `%TEMP%` старше двух суток;
  - `EXUI_HOST_TIMEOUT`, `EXUI_HOST_TRACE`.
- **Выпуск и проверки:**
  - `Package-Release.ps1` явно пишет `/` в путях ZIP и останавливается, если в имени записи есть `\`. Без этого запуск в Windows PowerShell 5.1 давал 25 путей через `\`.
  - Эталонный тест `.gdl`, бюджет обходов дерева, fuzz-тест `.exui`, CI на GitHub Actions.
  - Исправлено устаревшее ожидание порядка страниц в `archive-smoke` (`selected-frames`).
- EXUI/5, metadata schemas и plugin ID не менялись.

## Отклонено при проверке

Кэш поиска полей в хосте (P3) **не включён**. Значения проекта он не меняет, но `.gdl` выходил с другими байтами: .NET Framework упорядочивает сериализуемые поля типа по тому, как заполнялся кэш рефлексии, поэтому меньшее число вызовов `GetField` меняет порядок членов в BinaryFormatter. Расхождение нашёл эталонный тест — на всех шести пакетах. Причина записана в комментарии к `Find-TypeField`.
