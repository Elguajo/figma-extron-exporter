# Figma 0.2.0 и exui/5: расширенные сущности

20.10.2026. Работа в main по инструкции AGENTS.md. Запрос: стандарт и работающий экспорт перечисленных сущностей, включая плагин Figma; PDF с тремя колонками. Реализованный объём и совместимость: [D017](../../docs/decisions.md#d017---exui5-и-новые-нативные-элементы-figma-020), [контракт](../../docs/exui-v5.md), [план и влияние](../../docs/expanded-controls-implementation.md).

## Реализовано

| Поверхность | Изменение |
|---|---|
| Figma | Новые префиксы, предварительная таблица/сохранение ID, ручные свойства, до 8 состояний, выбор конкретного feedback для preview, экспорт всего проекта из выбранного дочернего элемента |
| Пакет | Строгий exui/5: один экран или контейнерный проект; новые нативные типы и programmer behavior; старые контракты 1-4 не изменялись |
| Writer | PBSlider, адресуемый PBLabel, PBShape, PBLine, PBDateTime, режимы PBLevel; страницы/popup/группы/ссылки переиспользуют прежний writer |
| Проверка | Независимое NRBF-чтение класса, ObjectTypeEnum, ID, геометрии, цветов, диапазона/ориентации, border resources, параметров бегунка, Line/DateTime и состояний |
| Документы | Стандарт 2.0, таблица в плагине и Markdown, отдельная трёхколоночная таблица и PDF, примеры для двух профилей |

Ссылка на PBShape/PBLine/PBDateTime добавлена в реестр уже существующих закреплённых доноров. Донорские бинарные файлы и SHA не менялись. PBSlider создаётся отдельно проверенным data-конструктором; это не универсальное создание нативных типов из JSON. DLL остаются в установленном GUI Designer, writer работает только в отдельном x86-хосте. Новых runtime-зависимостей или сети плагина нет.

## Исправления по проверкам и review

- Путь получения PBColor из донора при пустом нативном цвете исправлен: foreach теперь перечисляет страницы, а не List-обёртку. Новый PBSlider использует этот путь, прежние поля обычно уже имели цвет.
- Для корневых форм exui/5 использованы строгие ref-ветви oneOf, совместимые и с ограниченным evaluator, и с независимым Draft 2020-12. Неизвестные/смешанные поля не принимаются.
- Повреждённый реестр проекта/2 не может сбросить резервы удалённых контейнеров/групп. Nested registry входит в подпись устаревшего плана. Проверены rollback и счётчики после удаления/перестановки.
- Новые состояния сохраняют ID; preview может выбрать конкретный feedback вместо неоднозначной роли. Ошибка скопированного дочернего состояния не скрывает форму назначения родительской кнопки.
- В справочнике Slider и Value имеют разные смысловые суффиксы: slider_Volume и value_VolumeValue; одинаковый суффикс вызывал бы конфликт ключа.
- Неэкспортируемые свойства примитивов/частей Slider отклоняются: например, нецентрованный Track, несовпадающий radius Fill, неверный край заполнения, тени, неподдержанная форма Thumb. Старые error contracts сохранены.
- Read-only модель терпит отсутствие новых необязательных полей у прочих контролов/ресурсов; новые поля не должны ломать инвентаризацию старого документа.

## Граница результата и выпуск

Решение release-check: **SHIP WITH KNOWN RISKS для локальной проверки 0.2.0**. Код, готовый плагин, примеры, стандарт и PDF подготовлены; настоящие Figma/GUI Designer/Build/устройство остаются незакрытыми ручными проверками. Автоматическая проверка графа не доказывает внешний вид Slider/VolumeLED или Build нового типа.

Программа управления отдельно задаёт команды, обратную связь, начальное значение Slider, форматирование Value, переходы и начальные доступность/видимость. Их указания экспортируются в id-map, но не исполняются самим GDL. Изображения Track/Thumb, произвольные эффекты и AV-программа не реализованы. Видео и Dynamic Image для 1025M/300M отклоняются явно; для них нужны другие профили и отдельный проверенный срез.
