# Подготовка собственного Frame — 19.10.2026

## Наблюдение и причина

На скриншоте пользователя выбран Frame 1280×800, плагин 0.1.2 сообщает «Выберите подготовленный Frame экрана. Для первого запуска создайте демо». В `screenOf()` внешний Frame принимается только при наличии private metadata `kind=page`; выбор профиля в UI этого назначения не создаёт. Форма ручного назначения была скрыта в details, сообщение не объясняло путь для собственного макета.

Воспроизведение в built-plugin fixture: создать Frame 1280×800 без metadata и вызвать export. До подготовки пакета нет, ошибка `screen-unprepared` теперь указывает на конкретный следующий шаг.

## Изменение 0.1.3

- Для неназначенного Frame UI показывает кнопку подготовки и объясняет её пределы.
- Команда проверяет тип узла, выбранный профиль, точные размеры, существующие назначения и подготовленных предков до записи.
- На внешний Frame сохраняется page metadata; дочерние слои, их оформление и геометрия не меняются. Существующая page metadata сохраняется. Копии требуют явного переназначения.
- Документация объясняет подготовку собственного макета и ограничения блока громкости.

## Граница результата

Устранена непонятная остановка на неподготовленном внешнем Frame. Автоматическое преобразование произвольных вложенных макетов, скруглений и кастомных ползунков не реализовано. Совместимость конкретного макета пользователя нельзя установить по одному скриншоту; нужен исходный документ Figma. Настоящая Figma и GUI Designer в этом прогоне не запускались. Прежний подтверждённый реальный экспорт демо 300M не приписывается новому пользовательскому макету.
