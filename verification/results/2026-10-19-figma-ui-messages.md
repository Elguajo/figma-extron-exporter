# Figma plugin 0.1.1: заблокированные кнопки — 19.10.2026

## Наблюдение и воспроизведение

На [скриншоте пользователя](2026-10-19-figma-ui-messages/user-figma-before.png) плагин открыт в Figma, создано демо 300M и выбран Frame «Главная», но окно продолжает показывать первоначальный текст выбора, кнопки проверки/экспорта и создания демо выключены. Это подтверждает импорт и создание демо, но не полный экспорт.

В `src/figma-plugin/src/ui.ts` все входящие ответы отбрасывались при `event.source !== parent`. Отправка команды успевала заблокировать кнопки, а ответы `selection`, `success` и `idle` не обновляли состояние окна. [Контракт Figma](https://developers.figma.com/docs/plugins/creating-ui/) описывает получение `event.data.pluginMessage`; равенство `event.source` родительскому Window не гарантируется.

В настоящий Chromium добавлена доставка через моделируемый мост: `dispatchEvent(new MessageEvent('message', {data: {pluginMessage: ...}}))`, где source равен null. На старой сборке воспроизведён тот же разрыв: команда создания демо обработана, UI не принимает выбранный Frame — [before.txt](2026-10-19-figma-ui-messages/before.txt). Прежний тест моделировал только обычный parent.postMessage и эту ошибку не обнаруживал. Фактическое значение source внутри пользовательской Figma не было снято; связь конкретного скриншота с этим механизмом остаётся обоснованной гипотезой до повторного пользовательского прогона.

## Исправление и проверка

UI принимает документированную оболочку `pluginMessage` с объектом и строковым type, не требуя Window-источника от моста Figma. Сеть остаётся отключена, внешняя UI-страница не загружается. Схема пакета, semantic key, objectId/controlId, plugin ID, генератор и доноры не изменялись.

- Типы, 32 теста и сборка: [plugin-checks.txt](2026-10-19-figma-ui-messages/plugin-checks.txt).
- Chromium: прежний parent-сценарий и новый null-source сценарий; Frame виден в UI, кнопки восстанавливаются, проверка и download завершаются. Обе панели, форма, ошибки и textContent сохранены: [browser.json](2026-10-19-figma-ui-messages/browser.json), [лог](2026-10-19-figma-ui-messages/browser-tests.txt), [скриншот](2026-10-19-figma-ui-messages/bridge-ui.png). Figma host в обоих сценариях моделируется.
- Три скачанных пакета проверены настоящим CLI: [1025M](2026-10-19-figma-ui-messages/validate-1025m.json), [300M](2026-10-19-figma-ui-messages/validate-300m.json), [мост](2026-10-19-figma-ui-messages/validate-bridge.json). Оба профиля побайтово совпадают с примерами 0.1.0, уже прошедшими текущий writer 65/65; bridge download совпадает с обычным download. Генерация GDL для этого UI-исправления повторно не запускалась.
- [ZIP 0.1.1](../../releases/figma-plugin/Legacy/0.1.1/README.md) сохранён в Git, повторная упаковка побайтово равна; [SHA/размеры](2026-10-19-figma-ui-messages/file-hashes.json). Установленные runtime-файлы в локальном `releases/figma-plugin/0.1.0/unpacked` обновлены и совпадают со сборкой. Исходный ZIP 0.1.0 не менялся.

По указанию пользователя текущая правка перенесена из worktree в основную папку `main`, ветка `codex/figma-plugin` удалена после проверки, что её коммиты уже находятся в main. Дальнейшая работа непосредственно в main закреплена в `AGENTS.md`. Прежняя рабочая копия оставлена без активной ветки, её файлы не удалялись.

Закрыть окно плагина и запустить его снова из Development; увидеть 0.1.1 в заголовке, выбрать существующий Frame «Главная», проверить и скачать `.exui`. Подтвердить реальный PNG-рендер/metadata и оба профиля. GUI Designer/Build для реального экспорта Figma и устройство этим тестом не проверялись; Build не автоматизировался.
