# Figma → Extron Exporter — плагин 0.3.0 (Extron Kit preview)

В 0.3.0 добавлена кнопка **«Создать Extron Kit»**: 30 компонентов, свободное оформление кнопок в слотах Artwork, шаблоны проекта и пример выбранной панели. Figma MCP не используется; локальный плагин и слоты доступны на бесплатном тарифе. [Инструкция кита](EXTRON_KIT.md). Исторические примеры/ограничения ниже описывают прежние версии; для экземпляров компонентов и слотов применяется новая инструкция.

Локальный development-плагин Figma Design: подготовленный экран или проект → `.exui/1`, `.exui/3`, `.exui/4` или `.exui/5` → CLI → редактируемый `.gdl`. Оформление UI/UX и части механизма экспорта адаптированы из Baolv/figma-export по разрешению пользователя, подтвердившего наличие лицензии. [Происхождение кода](THIRD_PARTY_NOTICES.md).

**Для дизайнера:** [таблица префиксов и объяснений](PREFIXES.md), [полный стандарт v2.1](AUTHORING_STANDARD.md). В таблице есть страницы/popup, кастомный Slider, динамические значения, индикаторы, фигуры, линии, дата/время, логотипы и состояния кнопок. Тот же справочник раскрывается внутри плагина.

## Новое в 0.2.2

Новые кнопки разделены явно:

| Имя слоя | Состояния |
|---|---|
| `button_` / `btn_` | **Off + On**, ровно два |
| `feedbackbutton_` / `fbtn_` | **Normal + Active + Pressed**, ровно три |

В ручной форме добавлено поле «Тип кнопки», в таблице распознавания виден выбранный тип. Неверный набор состояний блокирует экспорт; недостающие виды не создаются автоматически. On/Active — feedback программы управления; отдельный press feedback включён только у второго типа.

Старые назначения остаются совместимыми и сохраняют ID/состояния. Для их явного перевода выбрать тип в форме и согласовать имена/роли/ID состояний; одно переименование слоя тип не меняет. Новые типы используют metadata/3, старый плагин 0.2.1 их отвергает. EXUI остаётся версии 5; готовый CLI 0.2.1 подходит. Новое демо использует Normal/Active/Pressed.

Касания и feedback на оборудовании ещё требуют проверки.

## Установка и первый экспорт

1. Распаковать готовый `figma-extron-plugin-0.3.0.zip` в постоянную папку. Либо собрать исходники командами ниже. `manifest.json` и папка `dist/` должны остаться рядом.
2. В **Figma Desktop** открыть новый тестовый Design-файл. Выбрать **Plugins → Development → Import plugin from manifest…**, указать `manifest.json` этого плагина.
3. Запустить **Figma → Extron Exporter**. Выбрать профиль панели и нажать **«Создать демо для этого профиля»**. В Figma должны быть доступны Arial Regular и Bold.
4. Оставить новый Frame выбранным. Нажать **«Проверить экран»**, затем **«Скачать .exui»**. Для второй панели создать отдельное демо.
5. Проверить скачанный файл и преобразовать в новый GDL из корня репозитория:

```powershell
& $dotnet run --project src/cli --no-build -- validate-package '<скачанный.exui>'
& $dotnet run --project src/cli --no-build -- convert-package '<скачанный.exui>' 'output/new-from-figma.gdl'
```

Для преобразования нужны закреплённые доноры и GUI Designer 1.28.0.7. Build выполняет пользователь внутри GUI Designer. Повторный экспорт создаёт новый проект и не сохраняет ручные правки GDL.

В manifest задан собственный стабильный development ID. Не менять его после сохранения назначений: private pluginData привязаны к ID плагина. Если Figma потребует выданный аккаунту ID для импорта/публикации, получить его через New plugin и установить **до** подготовки постоянного рабочего файла. Миграции между ID плагина нет. Настоящий экспорт демо 300M и Home 1025M подтверждён отдельными протоколами в verification/results; работа на оборудовании ещё требует проверки.

В 0.1.1 исправлена обработка ответов Figma: `event.data.pluginMessage` принимается и при `event.source=null`, как бывает при доставке через мост платформы. В 0.1.2 исправлен PNG-экспорт скрытых состояний: иконка экспортируется из временной видимой копии на странице с полными границами Frame, включая прозрачные поля, в Native 1×. Копия удаляется и при ошибке; видимость, родители и назначения исходных элементов не меняются. Проверка точного размера PNG сохранена, ошибка теперь показывает полученные и ожидаемые размеры.

В 0.1.3 добавлена кнопка **«Подготовить выбранный экран»** для собственного Frame без назначения. Она проверяет размер по выбранному профилю и сохраняет только назначение экрана (`page.home`, objectId 100, имя проекта из имени Frame). Слои, оформление и назначения дочерних элементов не меняются. Повторная подготовка не заменяет существующие ID; копии и элементы внутри подготовленного экрана отклоняются. Ошибка экспорта неподготовленного макета теперь объясняет последовательность действий.

В 0.1.4 добавлено распознавание имён с предварительным отчётом и отдельным сохранением назначений. Равнозначны `btn_` / `button_`, `lvl_` / `level_`, `txt_` / `text_`; для иконок — `Icon`, `ico_` / `icon_`. Внешний Frame может называться `Home`, `scr_Home` или `screen_Home`. Состояния Off/Normal и On/Feedback распознаются по ролям, Pressed необязателен. В каждом состоянии нужен Text; оформление и структуру распознавание не исправляет.

Существующие назначения остаются приоритетными, новые ID выдаются автоматически. Отдельные счётчики ID на экране сохраняют резерв удалённых автоматически выданных номеров. При изменении макета после отчёта требуется повторное распознавание. При ошибках запись не начинается; при отказе записи предпринимается восстановление исходных назначений, неполное восстановление сообщается отдельно.

В 0.1.5 добавлены `logo_`, `img_` / `image_` для самостоятельного PBImage и двухсостояниевая кнопка Normal/Pressed. Например, `button_VolumeUp` содержит обычный Normal и жёлтый Pressed; отдельный On не требуется. Регистр всего имени игнорируется при первом распознавании: `btn_volumeup` и `button_VolumeUp` дают один новый ключ `home.volumeup`. Существующие ключи и ID сохраняются, case-only дубликаты имён отклоняются.

После обновления файлов перезапустить плагин; в заголовке должна быть версия 0.3.0. Plugin ID сохранён. **Для логотипов и Normal/Pressed нужен обновлённый CLI с `.exui/4`**, для Off/On — `.exui/3`; пересобрать решение. Новые сущности и проект используют exui/5; для них нужен текущий CLI. Старые пакеты v1/v2/v3/v4 читаются без изменения их правил.

## Собственный макет и громкость

1. Создать внешний Frame `Home` размером 1280×800 или 320×480. Назвать непосредственные элементы, например `button_VolumeUp`, `level_Volume`, `text_VolumeValue`, `logo_Company`; допустимы короткие префиксы. Кнопки содержат Normal/Pressed, Off/On либо Off/On/Pressed.
2. Выбрать внешний Frame и профиль, нажать **«Распознать по именам»**, проверить отчёт, затем **«Сохранить распознанные назначения»**. При ошибках сначала исправить макет. Произвольные вложенные блоки автоматически не распознаются.
3. Ключи и ID новых элементов появятся в отчёте автоматически. Ручная форма остаётся доступной. Не менять назначенные ID при редактировании оформления. Для Text и graphic controlId не используется; для Value он обязателен.
4. Нажать **«Проверить экран»**, исправить указанные несовместимости, затем **«Скачать .exui»**. Наличие назначения страницы само по себе не подтверждает совместимость её содержимого.

Блок громкости состоит из отдельных Slider, трёх Button и Value. Простой level_ остаётся пустым Frame; кастомный slider_ содержит Track/Fill/Thumb. Новая схема поддерживает сплошные цвета и описанные в стандарте скругления, направление и диапазон. Изображения дорожки/бегунка и сложные эффекты пока не входят в поддержанное подмножество. Начальное и текущее значение, команды «+»/«−», шаг удержания, Mute и связь с динамическим Value задаёт программа Extron. Точный вид на панели требует ручной проверки.

Автоматический экспорт произвольного макета с сохранением всех элементов редактируемыми пока не реализован. Скриншот показывает внешний вид, но не структуру и назначения слоёв; для проверки конкретного макета нужен исходный Figma-документ.

## Имена слоёв и подготовка

Имена по стандарту нужны при первом автоматическом распознавании. После сохранения слой можно переименовать без смены ID. Ручные назначения со свободными именами остаются доступны. Metadata сохраняются через `node.setPluginData('exui', JSON)` со схемой `exui-node/1` для прежних назначений или `exui-node/2` для новых типов/свойств.

```text
Frame экрана                page: профиль, имя проекта, key, objectId
├── Frame кнопки            button: key, objectId, controlId
│   ├── Frame состояния     state: role=normal, stateId=0, stateName=Off
│   │   ├── Text            подпись на всю площадь состояния
│   │   └── Frame иконки    image: key, file, resourceName (необязательно)
│   ├── Frame состояния     state: role=feedback, stateId=1, stateName=On
│   └── Frame состояния     state: role=pressed, stateId=2, stateName=Pressed (необязательно)
├── Text                    label: key, objectId, controlId=null
└── Пустой Frame с fill     level: key, objectId, controlId
```

Для новых button_/btn_ распознаются только Off/On; для feedbackbutton_/fbtn_ — Normal/Active/Pressed. Прежние сохранённые Normal/Pressed, Off/On/Pressed и дополнительные feedback-состояния продолжают экспортироваться без миграции. Имена stateName и роли можно изменить через форму; порядок слоёв их не определяет. Для новых типов, дополнительных состояний, свойств или проекта выбирается `.exui/5`. Для прежнего подмножества graphic или Normal/Pressed выбирают `.exui/4`, Off/On — `.exui/3`, остальные экраны — `.exui/1`.

- Состояния занимают всю кнопку: `[0,0,width,height]`. Для предпросмотра видимо ровно одно; экспортируются все имеющиеся. Выбрать внешний Frame кнопки и нажать **«Показать состояние»**. Feedback задаёт внешняя программа управления, pressed — удержание; при отсутствии Pressed press feedback отключён. AV-логика не назначается.
- В каждом состоянии один Text на всю площадь: CENTER по горизонтали, CENTER/BOTTOM по вертикали. Читаются текст, цвет текста, fill и иконка. Шрифт одинаков во всех состояниях; виды различаются текстом, цветом или изображением.
- Label: LEFT/CENTER, в соответствии с наблюдаемым TextAlignment=3 закреплённого донора в сохранённом layout этапа 4. Другие выравнивания отклоняются: отдельного поля выравнивания Label в `.exui/1` нет.
- Только Arial Regular/Bold. Figma задаёт размер в px, контракт — в пунктах: **pt = px × 72/96**. Демо использует обратное преобразование. Визуальное совпадение текста на устройстве пока не подтверждено.
- Иконка: Frame, PNG 1× Native, по центру горизонтально; сверху или посередине вертикально. Размер PNG должен совпадать с размером Frame. Явные поля `assets/name.png` и ASCII `resourceName.png`. Иконку можно растеризовать, саму кнопку — нельзя.
- Логотип / изображение: отдельный Frame прямо в экране, без состояний и controlId; содержимое экспортируется в PNG 1× и отдельный нативный PBImage. Прозрачные пиксели поддерживаются. Векторы внутри PNG отдельно в GDL не редактируются; положение и ресурс PBImage остаются редактируемыми.
- Level: пустой Frame с SOLID fill; PBLevel Slider, слева направо, 0..100. В Figma это упрощённое представление цвета/геометрии, не симуляция регулятора GUI Designer.
- Экран ровно 1280×800 или 320×480, без автоматического масштабирования. Целые координаты и размеры в пределах экрана.
- В 0.3.0 поддержаны экземпляры компонентов с контрактной структурой кита; component sets и автоматический разбор Figma variants не поддержаны. Эффекты, градиенты и произвольные слои разрешены внутри растеризуемого Artwork, снаружи действуют ограничения нативных элементов. Страницы и popup экспортируются внутри обычного Frame project_.

## ID, копии и ошибки

`key`, `objectId`, `controlId` сохраняются после распознавания либо задаются вручную. Перемещение, переименование, оформление, порядок и переключение preview их не назначают заново. Имя слоя становится именем объекта Extron; имя слоя состояния не меняет его сохранённый stateName.

В metadata есть `ownerNodeId`: копия уже назначенного узла отклоняется до явного нового назначения через ручную форму. У скопированной кнопки нужно назначить внешний control и скопированные Frame состояний/иконок. Совместное использование image key разрешено только при одинаковых file/resourceName и PNG-байтах. Дубликаты ключей, objectId/controlId в одном экране отклоняются. Реестр `exui-id-registry/1` хранится отдельно на экране, `exui-id-registry/2` — на проекте, ключ `exui-id-registry`; это счётчики резерва, а не полная история назначений. ID резервируются перед записью узлов; при прерванной записи возможны пропуски. Ручные исторические ID и намеренное переиспользование между пакетами остаются ответственностью автора.

Ошибка рендера обязательной иконки останавливает экспорт. Один ключ с разными PNG запрещён. Изменение дизайна во время асинхронного экспорта прерывает операцию. Сеть отключена: `networkAccess.allowedDomains=['none']`. Полную структурную проверку PNG/CRC выполняет .NET reader после скачивания; кнопка «Проверить экран» сама по себе не проверяет все PNG.

## Сборка и проверки из корня репозитория

Node >=22.18, проверено на 24.21.0. Версии зависимостей закреплены lock-файлом:

```powershell
npm ci --prefix src/figma-plugin --ignore-scripts
npm run verify --prefix src/figma-plugin
npm run package --prefix src/figma-plugin
```

Последняя команда создаёт **новый** `output/figma-plugin/figma-extron-plugin-0.3.0.zip`. Для другого имени после сборки:

```powershell
node src/figma-plugin/package-plugin.mjs output/figma-plugin/another-name.zip
```

Проверка реального Chromium UI с моделируемыми сообщениями Figma:

```powershell
& ./src/figma-plugin/node_modules/.bin/playwright.cmd install chromium
npm run test:browser --prefix src/figma-plugin
```

Интеграция с настоящим .NET CLI после сборки решения:

```powershell
$env:DOTNET_EXE = '<полный путь к dotnet.exe>'
$env:EXUI_DONOR_REGISTRY = (Resolve-Path samples/donors.json).Path
node src/figma-plugin/test/native-integration.ts output/figma-plugin/new-run
```

Каталог результата должен быть новым. Создание/чтение документа моделирует fake Figma API; экспортёр/ZIP, CLI, донор и x86 Extron writer — настоящие. Проверяются два профиля: прежнее демо, 65/65 и сохранность ID после изменений; затем макет с префиксами и двумя состояниями, `.exui/3`, два состояния в GDL и press feedback -1. Дополнительно проверяются exui/4, все новые типы exui/5, состояния, страницы, обычный/модальный popup, группы и ссылки для обеих панелей. GUI Designer и Build тесты не запускают.
