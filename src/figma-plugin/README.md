# Figma → Extron Exporter — плагин 0.8.8 preview

**Русский** · [English](#english)

**Локальное обновление 28.10.2026 — переходы в GCP.** Цель перехода у кнопок, режим «По кнопке» и проверки этих связей удалены. Переходы и открытие/закрытие popup настраиваются в GCP после импорта. Прежние назначения читаются без изменения ID: `navigate` игнорируется, `shownBy: navigation` означает `program`. EXUI/5 и CLI совместимы с прежними пакетами. Структура popupref, popup-группы и стартовая страница сохранены. Перезапустите development-плагин после сборки.

**Локальное обновление — кнопки целиком в PNG.** Назовите карточку `imagebutton_VideoControl` или `ibtn_VideoControl`: фон, иконки и текст каждого состояния сохранят расположение из Figma. ID, действия и состояния остаются у Button. Префикс имеет приоритет над настройкой текста для GCP; подпись меняется в Figma с повторным экспортом. Подготовка состояний и нумерация поддерживают оба имени. Для нового рисунка примените обычную подготовку состояний; у существующей кнопки достаточно заменить префикс, сохранив оставшуюся часть имени. Обновлён development build; прежние архивы выпусков не изменены. [Подробности](NATIVE_TEXT.md#подписи-кнопок).

**0.8.7 — ID обратно из GUI Designer в Figma.** Экспортируйте EXUI, сопоставьте старые и новые кнопки в LayoutUpdater, сохраните «Карта ID → Figma…», затем откройте карту в плагине через «Назначения Extron → Импортировать карту ID из LayoutUpdater» и примените ко всем. Можно связывать кнопки с разными ID по одной либо группой. Следующий экспорт будет содержать номера GUI Designer.

**0.8.7 — имя копии экрана.** Копия `screen_AudioControl`, переименованная в `screen_VideoControl`, получает собственное имя проекта. Состав экспорта задаётся выделением фреймов или областью экспорта. Прежнее добавление экрана через цель перехода удалено в 0.8.8.

**0.8.5 — ручные ID и замена кнопок GUI Designer.** Выберите кнопку → «Назначение выбранного элемента» → «ID управления Extron» → «Сохранить ID». Можно взять ID кнопки, созданной только в GUI Designer, например `1`. Ошибки других слоёв и текущая область экспорта не мешают сохранению. Для переноса оформления в рабочий GDL используйте `updater/Extron.LayoutUpdater.exe` из CLI 0.8.5 и включите «Заменять оформление кнопок GUI Designer по ID управления». Внутренние ID и поведение рабочей кнопки сохраняются; ID, число и порядок состояний должны совпадать.

**0.8.2 — автоматическое положение текста кнопок.** Выделите кнопки, экран или popup, откройте «Текст кнопок для GCP» и один раз примените «Автоматически из Figma». При каждом экспорте положение текстовой рамки внутри кнопки определяет центр или низ; по горизонтали текст всегда по центру. Настройки абзаца игнорируются, рамка на всю кнопку означает центр. Подпись хранится в состояниях самого Button и заменяется через Text Feedback; отдельный Label и текст в PNG для неё не создаются. Фон, иконки, ID и исходные слои Figma сохраняются. Ручные Center / Bottom Center и отмена через «Сохранить расположение Figma» остаются доступны. Нужен CLI **0.8.2** (подходит и 0.8.1); EXUI/5 не изменён. [Правила автоматического режима](NATIVE_TEXT.md#автоматически-из-figma-плагин-082).

**Локальная актуализация Extron Kit от 24.10.2026 — Apple-inspired Light:** весь кит, состояния, шаблоны и примеры обеих панелей в едином светлом стиле с Inter и синим акцентом. Volume +/− и Back/Home/Settings — Normal / Pressed. Создать новый комплект: «Библиотека компонентов» → «Создать Extron Kit»; ревизия **2026-10-24-apple** показана на холсте. Существующие библиотеки автоматически не обновляются. Номер 0.7.3 сохранён; архив выпуска предшествует актуализации. [Инструкция](EXTRON_KIT.md).

**0.7.3 — нумерация кнопок.** Под «Оформление кнопок» добавлен независимый раскрывающийся блок **«Нумерация кнопок»**. Выделите сами кнопки в Figma; задайте основу имени и начальный номер, проверьте список и нажмите **«Пронумеровать»**. Опции **«Нумеровать имена слоёв»** и **«Обновлять текст кнопок»** независимы; обновление текста изначально выключено. [Установка 0.7.3](../../releases/figma-plugin/0.7.3/README.md).

- **Заново по расположению:** слева направо, сверху вниз (верхние края в пределах 2 px считаются одним рядом). В каждом непосредственном родителе отдельный счёт. Обрабатываются только непосредственно выделенные кнопки; выбор родительской группы, фрейма, секции или слоя внутри кнопки не включает кнопку в нумерацию. Префиксы `button_`, `btn_`, `feedbackbutton_`, `fbtn_` сохраняются. Основа применяется к выделенным кнопкам, включая кнопки с другими именами; перед применением проверьте предпросмотр.
- **Исправить только повторы:** занятые номера выбранной основы сохраняются, копии и кнопки без такого номера получают свободные, начиная с указанного. Сохранённый оригинал имеет приоритет над копиями. Невыбранные соседние кнопки резервируют свои номера и не меняются. Внутренние слои состояний и определения компонентов не нумеруются.
- **Обновление текста:** одна подпись в каждом состоянии, включая скрытые; также поддержана одна подпись в ещё не подготовленной кнопке. При нескольких Text-слоях, отсутствии подписи, недоступном шрифте или смешанном оформлении внутри Text плагин предлагает исправить структуру либо выключить обновление текста. Все шрифты загружаются до записи; изменившиеся выделение или макет требуют нового предпросмотра. Изменения можно отменить в Figma.
- Команда меняет только имена и выбранные подписи, без записи metadata. Object ID, Control ID и ID состояний сохраняются; автоматические ключи следуют новым именам при следующей проверке/выгрузке. Режим экспорта и сохранённый состав проекта не расширяют выделение. CLI и EXUI/5 не менялись. [Проверки и ограничения](../../docs/verification/results/2026-10-23-button-numbering.md).

**0.7.2 — выбор пары состояний:** в «Оформление кнопок» выберите **Off / On** либо **Normal / Pressed**. Override («Применить новый стиль и к готовым») преобразует готовые обычные пары в выбранную схему в обе стороны. Имена и роли назначений меняются вместе, ID кнопки и её слои сохраняются. Пропуск сохраняет готовые пары. [Установка](../../releases/figma-plugin/0.7.2/README.md).

Оформление кнопок и Override используют только текущее выделение Figma: один или несколько фреймов либо сами кнопки. Режим экспорта и сохранённый состав проекта не добавляют невыбранные фреймы.

**0.7.0 — контраст кнопок:** в «Оформление кнопок» включена настройка **«Исправлять контраст текста и иконок»**. При применении образцов сливающиеся с фоном однотонные цвета заменяются чёрным или белым отдельно в каждом изменяемом состоянии. Контрастные цвета сохраняются; сложные заливки и изображения отмечаются для ручной проверки. Настройку можно отключить. [Правила и ограничения](BUTTON_STATES.md#контраст-при-применении-оформления).

**Обновление 0.7.0 — оформление выбранного popup:** `popup_`, `modalpopup_`, `popupgroup_` и их дочерние слои задают область оформления во всех режимах экспорта, включая сохранённый проект. Недостающие состояния создаются внутри выбранного контейнера. Сообщение результата называет область и раздельно показывает подготовку кнопок, обновление готовых и создание состояний. [Установка](../../releases/figma-plugin/0.7.0/README.md).

**0.7.0 — чистые углы кнопок:** состояния кнопок с PNG экспортируются с прозрачной заливкой, поэтому на фоне-изображении у закруглённых кнопок нет белых углов. Выпускается вместе с CLI 0.7.0, который исправляет пустой preview страниц в GCP. [Установка](../../releases/figma-plugin/0.7.0/README.md).

**0.7.0 — popup и группы по имени:** новое `popupref_WallLayouts` автоматически связывается с соседним `popupgroup_WallLayouts`, а `popupref_Sources` — с `popup_Sources`. Это работает и при выборе только экранов в режимах «Выбранные фреймы» и «Текущая страница». При нескольких совпадениях выберите цель в «Содержимое места popup» и сохраните связь. Сохранённые назначения не заменяются. [Установка и правила](../../releases/figma-plugin/0.7.0/README.md).

**0.6.8 — связанные popup при экспорте экранов:** режимы «Выбранные фреймы» и «Текущая страница» включают сохранённые цели popupref, даже если после связывания выделены только экраны. Несвязанные группы не добавляются. Ошибки отсутствующей цели и несовпадения размеров разделены; отчёт показывает конкретный popupref. [Установка](../../releases/figma-plugin/0.6.8/README.md).

**0.6.7 — прозрачность линий:** Pen/Vector и Line Tool поддерживают непрозрачность SOLID Stroke и общую Opacity слоя; прямоугольные линии — Fill и Opacity. Линии остаются нативными PBLine. Нужен CLI **0.6.4**. [Установка](../../releases/figma-plugin/0.6.7/README.md).

Текущий комплект: **плагин 0.8.8 + CLI и LayoutUpdater 0.8.8**, единственный контракт пакетов — **EXUI/5**. CLI 0.7.0 пишет пустой Text у картинок, фигур, линий и регуляторов, чтобы GCP не оставлял страницу пустой, и сохраняет сравнение экспортов из 0.6.6 ([инструкция](../../docs/updating-configured-projects.md)). Начиная с CLI 0.6.5 устранены унаследованные заливки popup, принимает EXUI/5 прежних плагинов, прозрачные фоны popup/цвета фигур и ставит стартовую страницу первой при конвертации. Старые пакеты EXUI/1–4 актуальный CLI отклоняет: экспортируйте исходный макет заново. Сохранённые назначения и ID в Figma остаются на месте, ключи следуют именам слоёв; архивы прежних выпусков не меняются.

**0.6.6 — клиппинг растрового фона:** включите Clip content у экрана или popup. Выступающий за его границы Frame `image_Background` экспортируется только видимой частью PNG с прежним масштабом. Клиппинг самого `image_Background` обрезает его внутренний рисунок; для выхода самого Frame за экран нужен клиппинг у экрана. Исходные размеры и координаты не меняются. [Установка](../../releases/figma-plugin/0.6.6/README.md).

**0.6.5 — связи по именам:** выберите popupref → «Содержимое места popup» → popup/группа → «Сохранить связь popup». Ниже показаны сохранённые связи и кнопки перехода к ним на холсте; «Без связи» снимает назначение, не удаляя Frame (проект до нового связывания может не пройти проверку экспорта). Выделите кнопки одной страницы/popup → «Группа выбора кнопок» → создать из выделения или выбрать существующую → сохранить. Ключ назначается автоматически, ID остаются прежними. В проекте есть список стартовых экранов; возле перехода кнопки — «Показать цель в Figma». Все изменения связей сохраняются явно и остаются после перезапуска. Выбор и обратную связь кнопок по-прежнему подключает программа управления Extron. [Установка](../../releases/figma-plugin/0.6.5/README.md).

**0.6.4 — связь popup и память страницы:** пустой `popupref_…` можно сохранить без ключей и ID. Выделите popup вместе или их существующую группу → «Размещение popup» → выберите место по имени → «Связать с местом popup». Группа создаётся автоматически или переиспользуется, координаты и размеры popup сохраняются. Назначения записываются после кнопки «Сохранить назначение» и восстанавливаются после перезапуска. Профиль, режим экспорта и выбранный состав проекта сохраняются отдельно на странице Figma. Новая стартовая страница автоматически заменяет прежнюю. [Установка и правила](../../releases/figma-plugin/0.6.4/README.md).

**0.6.3 — стартовая страница и оформление кнопок в popup:** назначенная стартовая страница всегда первая в GDL; остальные идут по именам с учётом чисел. CLI 0.6.3 применяет это правило и к ранее сохранённым EXUI/5. Для `screen_StartPage` явно выберите «Показывается → Стартовая страница», у прежней стартовой — «Программой управления». Оформление кнопок можно применять к выбранному popup или группе popup без внешнего Frame проекта; при выборе одного popup соседние не меняются. [Правила](AUTHORING_STANDARD.md#7-страницы-и-popup).

**0.6.2 — оформление popup:** у Frame popup/popupref фон по умолчанию прозрачный, обводка не экспортируется, радиусы и Opacity самого Frame игнорируются. Цветные ориентиры можно оставить в макете. Для экспорта фона/обводки есть независимые флажки в форме назначения; содержимое popup сохраняет прежнее оформление. Ранее назначенные popup тоже используют прозрачный фон, пока экспорт фона не включён явно. Нужен CLI 0.6.1+. [Правила](AUTHORING_STANDARD.md#7-страницы-и-popup).

**0.6.1 — дата и время:** в Extron Kit — набор `datetime_Clock` с 28 форматами (24 пресета Pattern из GUI Designer 1.28 и 4 дополнительных, включая `MMMM d, h:mm tt`); формат выбирается свойством **Format**, текст показывает пример как в GUI Designer (`September 28, 12:00 AM`). Формат берётся из макета при каждой проверке: свойство Format, Text-слой `Pattern: …`, текст-пример из каталога или сам формат `HH:mm`. В форме — список форматов и живой пример; введённый формат сохраняется. CLI не изменился. [Подробнее](EXTRON_KIT.md#дата-и-время)

**0.6.0 — ключи по именам, латиница и порядок страниц:** ключи экранов и элементов следуют текущим именам слоёв при каждой проверке и скачивании (`page.home` → `page.audiocontrol`, `homeexportready.volume-2` → `audiocontrol.volume`), переходы обновляются, ID не меняются. Ключ, введённый вручную, сохраняется; пустое поле возвращает автоматический. Русские буквы в именах экранов, popup, групп и элементов запрещены, ошибка предлагает латинский вариант. Страницы идут в GDL по именам с учётом чисел: `screen_01-MainDashboard`, `screen_02-AudioControl`. Нативные подписи Inter не обрезаются. [Установка](../../releases/figma-plugin/0.6.0/README.md).

**0.5.5 — автоматический предпросмотр кнопок:** при проверке, скачивании и сохранении распознанных назначений лишние видимые состояния скрываются. Если видимы несколько, остаётся Off / Normal / Passive, когда оно среди видимых; иначе первое видимое состояние. Единственное видимое состояние, включая On / Active / Pressed, сохраняется. Если скрыты все, показывается обычное. Само распознавание только показывает план. Все состояния экспортируются, имена, оформление и ID сохраняются; при ошибке записи откатываются назначения и видимость. [Установка](../../releases/figma-plugin/0.5.5/README.md).

**0.5.4 — округление линий:** для Pen/Line Tool округляются толщина Stroke и прямоугольник окрашенной области. Дробная толщина (1.5 → 2) и дробные координаты больше не блокируют распознавание. Исходный слой не меняется; линия остаётся нативным PBLine без PNG. Длина должна быть больше толщины до и после округления. [Установка](../../releases/figma-plugin/0.5.4/README.md).

**0.5.3 — трансформации кнопок и текстовые компоненты:** поворот и отражение Group/Frame состояний и внешней кнопки сохраняются в PNG, включая унаследованные трансформации. Текст трансформированного состояния остаётся внутри PNG; кнопка сохраняет состояния и управляющий ID. Область нажатия в Extron — охватывающий прямоугольник кнопки. Состояния по-прежнему должны совпадать с границами кнопки. Text, Component/Instance с одним непосредственным Text и текстовые Frame кита поддерживаются для Label/Value/DateTime; Content должен занимать весь контейнер для нативного экспорта. DateTime и Value остаются нативными обновляемыми элементами. Произвольные многослойные компоненты автоматически не разбираются на нативные фигуры. [Установка](../../releases/figma-plugin/0.5.3/README.md).

**0.5.2 — ошибки имён и переход к слою:** отчёт указывает полное имя, позицию недопустимого символа и пример исправления (`line_Devider 4` → `line_Devider-4`). Действующие правила имён сохранены. «Показать слой» вычисляет центр по абсолютным координатам холста, учитывает вложенные контейнеры и поворот, корректно обрабатывает линии с нулевой шириной/высотой и ограничивает приближение до 200%. Для скрытых состояний положение вычисляется без изменения видимости. Имена, назначения и исходная геометрия не меняются.

**0.5.0:** Inter и Inter Display экспортируются нативным редактируемым текстом: 18 начертаний, Label/Value/DateTime и подписи Button. Шрифт встроен в GDL и поставляется с CLI; устанавливать его в Windows не требуется. Все девять выравниваний доступны для Label/Value/DateTime. Для Inter с общей одинаковой подписью во всех состояниях кнопки создаётся отдельный нативный Label в исходных координатах. Нужны обновлённые плагин **и CLI 0.5.0**; прежние EXUI/5 и назначения совместимы. [Правила текста](NATIVE_TEXT.md).

**История 0.4.5:** статические txt_/text_ с Inter и другими шрифтами автоматически экспортируются в PNG — Frame вручную не нужен. Сохраняются выравнивание и дробная геометрия; в Figma Text остаётся редактируемым. Arial Regular/Bold с нативным оформлением остаётся PBLabel. Value/DateTime требуют нативного Arial, чтобы их содержимое продолжало обновляться. Дробные размеры logo_/img_ тоже сохраняются внутри прозрачного PNG с целыми внешними границами.

**Локальный preview: оформление кнопок.** Кнопки и состояния могут быть **Group или Frame**. ## Состояния кнопок в текущем 0.5.0 preview

Единое правило для новых макетов: **Off / On** — включение или выбор; **Normal / Pressed** — нажатие и удержание; **Normal / Active / Pressed** — выбор с отдельным видом нажатия. Первые две схемы используют `button_` / `btn_`, третья — `feedbackbutton_` / `fbtn_`. Прежние Passive / Active, Normal / Active без Pressed и другие поддержанные синонимы остаются совместимыми. Готовые имена и ID не меняются. [Подготовка и образцы Rectangle](BUTTON_STATES.md).

В обновлённом exui/5 снят отдельный предел числа PNG. Для большого экрана нужен **CLI 0.3.0 preview** вместе с обновлённым плагином; прежний CLI 0.2.1 поддерживает только пакеты до 16 PNG. Сохраняются ограничения: 4 MiB на PNG, 16 MiB распакованный пакет, manifest.json 64 KiB и screen.json 256 KiB. Прежние EXUI 1–4 не изменены.

В именах слоёв разрешены точки между непустыми частями: `button_side.hall` → ключ `home.side.hall`. Авторское имя сохраняется в GDL, переименование в SideHall не требуется. Имена — строки, controlId остаётся числовым; точка не задаёт исполняемый код и не создаёт группу выбора автоматически.

Экспортируются только состояния, которые есть в макете. Обычная `button_` / `btn_` принимает два состояния: Off / On, Passive / Active или Normal / Pressed. Для `feedbackbutton_` / `fbtn_` достаточно Normal / Active (также Passive / Active или Off / On); Pressed необязателен. Имена Normal / Off / Passive обозначают normal, On / Active / Feedback — feedback. Отсутствующий Pressed и его PNG не создаются. Скрытые существующие состояния сохраняются при экспорте. Карта ID содержит группу выбора, но переключение Hall/Terrace выполняет программа Extron.

## Выбранные фреймы в одном проекте — без секции

Связывать кнопки с экранами перед экспортом не требуется. Ключи и ID назначаются при проверке и скачивании; переходы настраиваются в GCP.

1. На открытой странице Figma выделить вместе `screen_Main` и `screen_AudioControl`. В меню «Что экспортировать» автоматически включится «Выбранные фреймы — один проект»; вариант можно выбрать и вручную.
2. Выбрать профиль панели → «Проверить макет» или сразу «Скачать .exui». Ключи, свободные ID и имя проекта заполняются автоматически. Первой новой странице в порядке выделения назначается стартовый показ; имя проекта берётся из имени файла Figma. При необходимости сначала просмотреть результат через «Распознать по именам».
3. Преобразовать EXUI в GDL, выполнить Verify и Save and Build в GUI Designer, затем импортировать интерфейс в GCP и настроить действия кнопок.

Плагин помнит набор экранов до закрытия или смены страницы. Можно выделять кнопки и отдельные страницы для настройки свойств, состав проекта сохраняется. Новое выделение нескольких фреймов заменяет набор; после перезапуска нужно выделить их заново. Посторонние фреймы не получают назначений и не экспортируются. Слои не перемещаются, обёртка не создаётся. Реестр проекта хранится в служебных данных открытой страницы.

«Экраны текущей страницы — один проект» собирает `screen_`, `scr_`, `Home` и ранее назначенные страницы точного размера выбранной панели; секции и известные Frame-проекты просматриваются для поиска экранов. Черновые фреймы, текстовые подписи, компоненты и экраны другого размера исключаются. Другие страницы документа не читаются. Для popup и их групп используйте явное выделение нужных Frame либо прежний экспорт секции / Frame проекта.

Прежние назначения сохраняются. Если экраны ранее были независимо подготовлены с одинаковыми ID либо несколькими стартовыми страницами, проверка покажет конфликт; автоматического переназначения старых ID нет. В одном проекте используется один профиль панели. Переходы между страницами и popup на панели настраиваются в GCP.

## Проект из секции и переходы

Секция — организационный контейнер, её размер и оформление не экспортируются. Экраны внутри остаются Frame точного размера панели. При первом распознавании первой странице в порядке слоёв назначается стартовый показ, остальным — показ программой. Ровно одна страница должна остаться стартовой; это меняется в «Назначение выбранного элемента → Показывается».

Переходы между экранами и открытие/закрытие popup задавайте в GCP. В плагине сохраняйте стартовую страницу, размещение popup и идентификаторы элементов; цели переходов у кнопок не нужны.

Frame `project_Trilliant` продолжает работать. Ключ секции при новом распознавании — `project.section`, имя проекта берётся из заголовка секции; ключи и ID её страниц/элементов выдаются прежним реестром. После подготовки секции проверка и экспорт доступны и при выделении её дочернего элемента. Для распознавания нужно выбрать саму секцию или внешний Frame.

## Установка и первый экспорт

1. Распаковать готовый `figma-extron-plugin-0.3.3.zip` в постоянную папку. Либо собрать исходники командами ниже. `manifest.json` и папка `dist/` должны остаться рядом.
2. В **Figma Desktop** открыть рабочий Design-файл. Выбрать **Plugins → Development → Import plugin from manifest…**, указать `manifest.json` этого плагина.
3. Запустить **Figma → Extron Exporter**. Выбрать профиль панели и секцию с Frame страницами (`screen_MainDashboard`, `screen_AudioControl`) либо один Frame экрана. В секции допускаются непосредственно страницы, popup и Frame групп popup; вложенные секции и произвольные подписи вне страниц не экспортируются. Секция может называться по-русски, префикс `project_` ей не нужен.
4. Нажать **«Распознать по именам»**, проверить список и **«Сохранить распознанные назначения»**. Затем **«Проверить макет» → «Скачать .exui»**. Если нужны готовые элементы, раскрыть **«Библиотека компонентов» → «Создать Extron Kit»**. Это дополнительное действие; демо-кнопки в текущем UI нет.
5. Проверить скачанный файл и преобразовать в новый GDL из корня репозитория:

```powershell
& $dotnet run --project src/cli --no-build -- validate-package '<скачанный.exui>'
& $dotnet run --project src/cli --no-build -- convert-package '<скачанный.exui>' 'output/new-from-figma.gdl'
```

Для преобразования нужны закреплённые доноры и GUI Designer с подходящим профилем совместимости CLI; исходная база — 1.28.0.7. Плагин экспортирует EXUI независимо от версии Extron. Новая локальная сборка CLI содержит `doctor` и `--compatibility` для диагностики и подключения обновлений; [порядок проверки GUI Designer и GCP](../../docs/extron-compatibility.md). Build выполняет пользователь внутри GUI Designer. Повторный экспорт создаёт новый проект и не сохраняет ручные правки GDL.

В manifest задан собственный стабильный development ID. Не менять его после сохранения назначений: private pluginData привязаны к ID плагина. Если Figma потребует выданный аккаунту ID для импорта/публикации, получить его через New plugin и установить **до** подготовки постоянного рабочего файла. Миграции между ID плагина нет. Настоящий экспорт демо 300M и Home 1025M подтверждён отдельными протоколами в docs/verification/results; работа на оборудовании ещё требует проверки.

В 0.1.1 исправлена обработка ответов Figma: `event.data.pluginMessage` принимается и при `event.source=null`, как бывает при доставке через мост платформы. В 0.1.2 исправлен PNG-экспорт скрытых состояний: иконка экспортируется из временной видимой копии на странице с полными границами Frame, включая прозрачные поля, в Native 1×. Копия удаляется и при ошибке; видимость, родители и назначения исходных элементов не меняются. Проверка точного размера PNG сохранена, ошибка теперь показывает полученные и ожидаемые размеры.

В 0.1.3 добавлена кнопка **«Подготовить выбранный экран»** для собственного Frame без назначения. Она проверяет размер по выбранному профилю и сохраняет только назначение экрана (`page.home`, objectId 100, имя проекта из имени Frame). Слои, оформление и назначения дочерних элементов не меняются. Повторная подготовка не заменяет существующие ID; копии и элементы внутри подготовленного экрана отклоняются. Ошибка экспорта неподготовленного макета теперь объясняет последовательность действий.

В 0.1.4 добавлено распознавание имён с предварительным отчётом и отдельным сохранением назначений. Равнозначны `btn_` / `button_`, `lvl_` / `level_`, `txt_` / `text_`; для иконок — `Icon`, `ico_` / `icon_`. Внешний Frame может называться `Home`, `scr_Home` или `screen_Home`. Состояния Off/Normal и On/Feedback распознаются по ролям, Pressed необязателен. В каждом состоянии нужен Text; оформление и структуру распознавание не исправляет.

Существующие назначения остаются приоритетными, новые ID выдаются автоматически. Отдельные счётчики ID на экране сохраняют резерв удалённых автоматически выданных номеров. При изменении макета после отчёта требуется повторное распознавание. При ошибках запись не начинается; при отказе записи предпринимается восстановление исходных назначений, неполное восстановление сообщается отдельно.

В 0.1.5 добавлены `logo_`, `img_` / `image_` для самостоятельного PBImage и двухсостояниевая кнопка Normal/Pressed. Например, `button_VolumeUp` содержит обычный Normal и жёлтый Pressed; отдельный On не требуется. Регистр всего имени игнорируется при первом распознавании: `btn_volumeup` и `button_VolumeUp` дают один новый ключ `home.volumeup`. Существующие ключи и ID сохраняются, case-only дубликаты имён отклоняются.

После обновления файлов перезапустить плагин; в заголовке должна быть версия 0.5.0. Plugin ID сохранён. Использовать CLI 0.5.0 вместе с текущим samples/donors.json. Все экраны и проекты экспортируются в EXUI/5; чтение старых пакетов удалено из текущего CLI.

## Собственный макет и громкость

1. Создать внешний Frame `Home` размером 1280×800 или 320×480. Назвать непосредственные элементы, например `button_VolumeUp`, `level_Volume`, `text_VolumeValue`, `logo_Company`; допустимы короткие префиксы. Кнопки содержат Normal/Pressed, Off/On либо Off/On/Pressed.
2. Выбрать внешний Frame и профиль, нажать **«Распознать по именам»**, проверить отчёт, затем **«Сохранить распознанные назначения»**. При ошибках сначала исправить макет. Произвольные вложенные блоки автоматически не распознаются.
3. Ключи и ID новых элементов появятся в отчёте автоматически. Ручная форма остаётся доступной. Не менять назначенные ID при редактировании оформления. Для Text и graphic controlId не используется; для Value он обязателен.
4. Нажать **«Проверить макет»**, исправить указанные несовместимости, затем **«Скачать .exui»**. Наличие назначения страницы само по себе не подтверждает совместимость её содержимого.

Блок громкости состоит из отдельных Slider, трёх Button и Value. Простой level_ остаётся пустым Frame; кастомный slider_ содержит Track/Fill/Thumb. Новая схема поддерживает сплошные цвета и описанные в стандарте скругления, направление и диапазон. Изображения дорожки/бегунка и сложные эффекты пока не входят в поддержанное подмножество. Начальное и текущее значение, команды «+»/«−», шаг удержания, Mute и связь с динамическим Value задаёт программа Extron. Точный вид на панели требует ручной проверки.

Автоматический экспорт произвольного макета с сохранением всех элементов редактируемыми пока не реализован. Скриншот показывает внешний вид, но не структуру и назначения слоёв; для проверки конкретного макета нужен исходный Figma-документ.

## Имена слоёв и подготовка

Имена по стандарту нужны при первом автоматическом распознавании. После сохранения слой можно переименовать без смены ID. Ручные назначения со свободными именами остаются доступны. Metadata сохраняются через `node.setPluginData('exui', JSON)` со схемой `exui-node/1` для прежних назначений или `exui-node/2` для новых типов/свойств.

```text
Frame экрана                page: профиль, имя проекта, key, objectId
├── Frame кнопки            button: key, objectId, controlId
│   ├── Frame состояния     state: role=normal, stateId=0, stateName=Off
│   │   ├── Text            подпись на всю площадь состояния
│   │   └── Frame иконки    image: key, file, resourceName (необязательно)
│   ├── Frame состояния     state: role=feedback, stateId=1, stateName=On
│   └── Frame состояния     state: role=pressed, stateId=2, stateName=Pressed (необязательно)
├── Text                    label: key, objectId, controlId=null
└── Пустой Frame с fill     level: key, objectId, controlId
```

В текущем preview новые button_/btn_ принимают Off/On, Passive/Active или Normal/Pressed; feedbackbutton_/fbtn_ — normal и feedback с необязательным pressed. Синонимы описаны выше. Прежние сохранённые назначения и дополнительные feedback-состояния продолжают экспортироваться без миграции. Имена stateName и роли можно изменить через форму; порядок слоёв их не определяет. Все экраны и проекты используют `.exui/5`; типы элементов и metadata больше не выбирают версию пакета.

- Состояния занимают всю кнопку: `[0,0,width,height]`. Для предпросмотра видимо ровно одно; экспортируются все имеющиеся. Выбрать внешний Frame кнопки и нажать **«Показать состояние»**. Feedback задаёт внешняя программа управления, pressed — удержание; при отсутствии Pressed press feedback отключён. AV-логика не назначается.
- В каждом состоянии один Text на всю площадь: CENTER по горизонтали, CENTER/BOTTOM по вертикали. Читаются текст, цвет текста, fill и иконка. Шрифт одинаков во всех состояниях; виды различаются текстом, цветом или изображением.
- Нативный Label: Arial Regular/Bold, Inter и Inter Display (18 начертаний), девять выравниваний. Сложное оформление, другие семейства и дробная геометрия статического текста сохраняются в PNG; источник в Figma остаётся Text. [Условия редактируемого экспорта](NATIVE_TEXT.md).
- Value и DateTime также поддерживают Inter / Inter Display и девять выравниваний, сохраняя обновление содержимого. Figma задаёт размер в px, контракт — в пунктах: **pt = px × 72/96**. Демо использует обратное преобразование. Визуальное совпадение нативного текста на устройстве пока не подтверждено.
- В прежней нативной схеме иконка — Frame, PNG 1× Native, по центру горизонтально; сверху или посередине вертикально. В составной схеме Group/Frame оформление всего состояния может экспортироваться в PNG, а кнопка остаётся нативным PBButton с controlId и состояниями. [Правила сохранения редактируемого текста](BUTTON_STATES.md).
- Логотип / изображение: отдельный Frame прямо в экране, без состояний и controlId; содержимое экспортируется в PNG 1× и отдельный нативный PBImage. Прозрачные пиксели поддерживаются. Векторы внутри PNG отдельно в GDL не редактируются; положение и ресурс PBImage остаются редактируемыми.
- Level: пустой Frame с SOLID fill; PBLevel Slider, слева направо, 0..100. В Figma это упрощённое представление цвета/геометрии, не симуляция регулятора GUI Designer.
- Экран ровно 1280×800 или 320×480, без автоматического масштабирования. Нативные элементы имеют целые координаты и размеры в пределах экрана. Для дробной графики и статического текста используется прозрачный целочисленный PNG-контейнер: исходная геометрия не округляется и не масштабируется.
- В 0.3.0 поддержаны экземпляры компонентов с контрактной структурой кита; component sets и автоматический разбор Figma variants не поддержаны. Эффекты, градиенты и произвольные слои разрешены внутри растеризуемого Artwork, снаружи действуют ограничения нативных элементов. Страницы и popup экспортируются внутри секции либо обычного Frame project_.

## ID, копии и ошибки

`key`, `objectId`, `controlId` сохраняются после распознавания либо задаются вручную. Перемещение, переименование, оформление, порядок и переключение preview их не назначают заново. Имя слоя становится именем объекта Extron; имя слоя состояния не меняет его сохранённый stateName.

В metadata есть `ownerNodeId`: при подготовке к экспорту плагин распознаёт копии и выдаёт им новые назначения, включая состояния и иконки кнопок. Оригиналы получают приоритет даже при перестановке копии выше в слоях. Дубликаты ключей, objectId в контейнере и controlId во всём проекте исправляются в предварительном плане, затем сохраняются вместе. Совместное использование image key разрешено только при одинаковых file/resourceName и PNG-байтах. Реестр `exui-id-registry/1` хранится отдельно на экране, `exui-id-registry/2` — на проекте, ключ `exui-id-registry`; это счётчики резерва, а не полная история назначений. Скопированный реестр используется как нижняя граница резерва ID. ID резервируются перед записью узлов; при прерванной записи возможны пропуски. Ручные исторические ID и намеренное переиспользование между пакетами остаются ответственностью автора. Ссылки внутри скопированного проекта обновляются вместе с целями; неоднозначная ссылка на прежний дублированный ключ сохраняет оставшуюся цель с этим ключом. Одинаковые имена страниц получают разные имена только в пакете, слои Figma не переименовываются.

Ошибка рендера обязательной иконки останавливает экспорт. Один ключ с разными PNG запрещён. Изменение дизайна во время асинхронного экспорта прерывает операцию. Сеть отключена: `networkAccess.allowedDomains=['none']`. Полную структурную проверку PNG/CRC выполняет .NET reader после скачивания; кнопка «Проверить макет» сама по себе не проверяет все PNG.

## Button states in the current 0.5.0 preview

## Layer names and preparation

Standard names are needed for the first automatic recognition. After saving, a layer can be renamed without changing its ID. Manual assignments with free names remain available. Metadata is saved through `node.setPluginData('exui', JSON)` with the `exui-node/1` schema for earlier assignments or `exui-node/2` for new types/properties.

```text
Screen Frame                page: profile, project name, key, objectId
├── Button Frame            button: key, objectId, controlId
│   ├── State Frame         state: role=normal, stateId=0, stateName=Off
│   │   ├── Text            caption over the whole state area
│   │   └── Icon Frame      image: key, file, resourceName (optional)
│   ├── State Frame         state: role=feedback, stateId=1, stateName=On
│   └── State Frame         state: role=pressed, stateId=2, stateName=Pressed (optional)
├── Text                    label: key, objectId, controlId=null
└── Empty Frame with fill   level: key, objectId, controlId
```

In the current preview, new button_/btn_ accept Off/On, Passive/Active or Normal/Pressed; feedbackbutton_/fbtn_ accept normal and feedback with an optional pressed. Synonyms are described above. Earlier saved assignments and extra feedback states keep being exported without migration. stateName values and roles can be changed in the form; the layer order does not define them. All screens and projects use `.exui/5`; element types and metadata no longer choose the package version.

- States cover the whole button: `[0,0,width,height]`. Exactly one is visible for the preview; all existing ones are exported. Select the outer button Frame and click **«Показать состояние»** (Show state). Feedback is set by the external control program, pressed means holding; without Pressed, press feedback is off. No AV logic is assigned.
- Each state has one Text over the whole area: CENTER horizontally, CENTER/BOTTOM vertically. The text, text color, fill and icon are read. The font is the same in all states; the looks differ by text, color or image.
- Native Label: Arial Regular/Bold, Inter and Inter Display (18 styles), nine alignments. Complex styling, other families and fractional geometry of static text are kept in PNG; the source in Figma stays a Text. [Conditions for editable export](NATIVE_TEXT.md#english).
- Value and DateTime also support Inter / Inter Display and nine alignments, keeping their content updatable. Figma sets the size in px, the contract in points: **pt = px × 72/96**. The demo uses the reverse conversion. Visual match of native text on the device is not confirmed yet.
- In the earlier native scheme, the icon is a Frame, PNG 1× Native, centered horizontally; at the top or in the middle vertically. In the composite Group/Frame scheme, the styling of the whole state can be exported to PNG while the button stays a native PBButton with a controlId and states. [Rules for keeping text editable](BUTTON_STATES.md#english).
- Logo / image: a separate Frame directly in the screen, without states and controlId; the content is exported to PNG 1× and a separate native PBImage. Transparent pixels are supported. Vectors inside the PNG are not editable separately in the GDL; the PBImage position and resource stay editable.
- Level: an empty Frame with a SOLID fill; PBLevel Slider, left to right, 0..100. In Figma this is a simplified color/geometry representation, not a simulation of the GUI Designer slider.
- The screen is exactly 1280×800 or 320×480, with no automatic scaling. Native elements have whole coordinates and sizes within the screen. Fractional artwork and static text use a transparent whole-pixel PNG container: the source geometry is not rounded or scaled.
- 0.3.0 supports component instances with the kit's contract structure; component sets and automatic parsing of Figma variants are not supported. Effects, gradients and arbitrary layers are allowed inside the rasterized Artwork; outside it, the native element limits apply. Pages and popups are exported inside a section or an ordinary project_ Frame.

## IDs, copies and errors

`key`, `objectId` and `controlId` are kept after recognition or set by hand. Moving, renaming, styling, ordering and switching the preview do not reassign them. The layer name becomes the name of the Extron object; the name of a state layer does not change its saved stateName.

The metadata has an `ownerNodeId`: when preparing the export, the plugin recognizes copies and gives them new assignments, including the states and icons of buttons. Originals take precedence even if a copy is moved above them in the layers. Duplicate keys, objectIds within a container and controlIds across the project are fixed in a preliminary plan, then saved together. Sharing an image key is allowed only with identical file/resourceName and PNG bytes. The `exui-id-registry/1` registry is stored separately on the screen, `exui-id-registry/2` on the project, under the `exui-id-registry` key; these are reserve counters, not a full history of assignments. A copied registry is used as the lower bound of the ID reserve. IDs are reserved before nodes are written; an interrupted write may leave gaps. Manual historical IDs and intentional reuse between packages remain the author's responsibility. Links inside a copied project are updated together with their targets; an ambiguous link to an earlier duplicated key keeps the remaining target with that key. Identical page names get different names only in the package; Figma layers are not renamed.

A render error of a required icon stops the export. One key with different PNGs is forbidden. Changing the design during an asynchronous export aborts the operation. Network access is off: `networkAccess.allowedDomains=['none']`. The full structural PNG/CRC check is done by the .NET reader after download; the «Проверить макет» (Check layout) button by itself does not check all PNGs.
