# Figma → Extron Exporter — плагин 0.1.0

Локальный development-плагин Figma Design: подготовленный Frame → `.exui/1` → существующий CLI → редактируемый `.gdl`. Оформление UI/UX и части механизма экспорта адаптированы из Baolv/figma-export по разрешению пользователя, подтвердившего наличие лицензии. [Происхождение кода](THIRD_PARTY_NOTICES.md).

## Установка и первый экспорт

1. Распаковать готовый `figma-extron-plugin-0.1.0.zip` в постоянную папку. Либо собрать исходники командами ниже. `manifest.json` и папка `dist/` должны остаться рядом.
2. В **Figma Desktop** открыть новый тестовый Design-файл. Выбрать **Plugins → Development → Import plugin from manifest…**, указать `manifest.json` этого плагина.
3. Запустить **Figma → Extron Exporter**. Выбрать профиль панели и нажать **«Создать демо для этого профиля»**. В Figma должны быть доступны Arial Regular и Bold.
4. Оставить новый Frame выбранным. Нажать **«Проверить экран»**, затем **«Скачать .exui»**. Для второй панели создать отдельное демо.
5. Проверить скачанный файл и преобразовать в новый GDL из корня репозитория:

```powershell
& $dotnet run --project src/cli --no-build -- validate-package '<скачанный.exui>'
& $dotnet run --project src/cli --no-build -- convert-package '<скачанный.exui>' 'output/new-from-figma.gdl'
```

Для преобразования нужны закреплённые доноры и GUI Designer 1.28.0.7. Build выполняет пользователь внутри GUI Designer. Повторный экспорт создаёт новый проект и не сохраняет ручные правки GDL.

В manifest задан собственный стабильный development ID. Не менять его после сохранения назначений: private pluginData привязаны к ID плагина. Если Figma потребует выданный аккаунту ID для импорта/публикации, получить его через New plugin и установить **до** подготовки постоянного рабочего файла. Миграции между ID плагина нет. Импорт в настоящий Figma Desktop пока требует ручной проверки.

## Имена слоёв и подготовка

Специальные имена не нужны: слой можно переименовать без смены ID. Назначение задаётся через **«Назначение выбранного элемента»** и сохраняется как `node.setPluginData('exui', JSON)` со схемой `exui-node/1`.

```text
Frame экрана                page: профиль, имя проекта, key, objectId
├── Frame кнопки            button: key, objectId, controlId
│   ├── Frame состояния     state: role=normal, stateId=0, stateName=Off
│   │   ├── Text            подпись на всю площадь состояния
│   │   └── Frame иконки    image: key, file, resourceName (необязательно)
│   ├── Frame состояния     state: role=feedback, stateId=1, stateName=On
│   └── Frame состояния     state: role=pressed, stateId=2, stateName=Pressed
├── Text                    label: key, objectId, controlId=null
└── Пустой Frame с fill     level: key, objectId, controlId
```

Три Frame просто с именами normal/feedback/pressed не заменяют явные назначения. Имена stateName и роли можно изменить через форму; порядок слоёв их не определяет.

- Состояния занимают всю кнопку: `[0,0,width,height]`. Для предпросмотра видимо ровно одно; экспортируются все три. Выбрать внешний Frame кнопки и нажать **«Показать состояние»**. Feedback задаёт внешняя программа управления, pressed — удержание; AV-логика не назначается.
- В каждом состоянии один Text на всю площадь: CENTER по горизонтали, CENTER/BOTTOM по вертикали. Читаются текст, цвет текста, fill и иконка. Шрифт одинаков во всех состояниях; виды различаются текстом, цветом или изображением.
- Label: LEFT/CENTER, в соответствии с наблюдаемым TextAlignment=3 закреплённого донора в сохранённом layout этапа 4. Другие выравнивания отклоняются: отдельного поля выравнивания Label в `.exui/1` нет.
- Только Arial Regular/Bold. Figma задаёт размер в px, контракт — в пунктах: **pt = px × 72/96**. Демо использует обратное преобразование. Визуальное совпадение текста на устройстве пока не подтверждено.
- Иконка: Frame, PNG 1× Native, по центру горизонтально; сверху или посередине вертикально. Размер PNG должен совпадать с размером Frame. Явные поля `assets/name.png` и ASCII `resourceName.png`. Иконку можно растеризовать, саму кнопку — нельзя.
- Level: пустой Frame с SOLID fill; PBLevel Slider, слева направо, 0..100. В Figma это упрощённое представление цвета/геометрии, не симуляция регулятора GUI Designer.
- Экран ровно 1280×800 или 320×480, без автоматического масштабирования. Целые координаты и размеры в пределах экрана.
- Не поддержаны instances/component sets, автоматический разбор стандартных Figma variants, группы контролов, несколько страниц, навигация, opacity, gradients, strokes, эффекты и скругления вне растровой иконки. Неподдерживаемое оформление отклоняется.

## ID, копии и ошибки

`key`, `objectId`, `controlId` задаются явно. Перемещение, переименование, оформление, порядок и переключение preview их не назначают заново. Имя слоя становится понятным именем объекта Extron; имя слоя состояния не меняет его сохранённый stateName.

В metadata есть `ownerNodeId`: копия узла отклоняется до явного нового назначения. У скопированной кнопки нужно назначить внешний control и скопированные Frame состояний/иконок. Совместное использование image key разрешено только при одинаковых file/resourceName и PNG-байтах. Дубликаты ключей, objectId/controlId в одном экране отклоняются. Исторического реестра ID и tombstones пока нет; намеренное повторное использование ID между разными пакетами остаётся ответственностью автора.

Ошибка рендера обязательной иконки останавливает экспорт. Один ключ с разными PNG запрещён. Изменение дизайна во время асинхронного экспорта прерывает операцию. Сеть отключена: `networkAccess.allowedDomains=['none']`. Полную структурную проверку PNG/CRC выполняет .NET reader после скачивания; кнопка «Проверить экран» сама по себе не проверяет все PNG.

## Сборка и проверки из корня репозитория

Node >=22.18, проверено на 24.21.0. Версии зависимостей закреплены lock-файлом:

```powershell
npm ci --prefix src/figma-plugin --ignore-scripts
npm run verify --prefix src/figma-plugin
npm run package --prefix src/figma-plugin
```

Последняя команда создаёт **новый** `output/figma-plugin/figma-extron-plugin-0.1.0.zip`. Для другого имени после сборки:

```powershell
node src/figma-plugin/package-plugin.mjs output/figma-plugin/another-name.zip
```

Проверка реального Chromium UI с моделируемыми сообщениями Figma:

```powershell
& ./src/figma-plugin/node_modules/.bin/playwright.cmd install chromium
npm run test:browser --prefix src/figma-plugin
```

Интеграция с настоящим .NET CLI после сборки решения:

```powershell
$env:DOTNET_EXE = '<полный путь к dotnet.exe>'
$env:EXUI_DONOR_REGISTRY = (Resolve-Path samples/donors.json).Path
node src/figma-plugin/test/native-integration.ts output/figma-plugin/new-run
```

Каталог результата должен быть новым. Создание/чтение документа моделирует fake Figma API; экспортёр/ZIP, CLI, донор и x86 Extron writer — настоящие. Проверяются два профиля, 61/61 и сохранность ID после изменений. GUI Designer и Build тесты не запускают.

## Граница подтверждения

Автоматические проверки плагина, реальный Chromium и преобразование через CLI покрывают реализованный путь. Они **не подтверждают** реальный импорт в Figma Desktop, доступность Arial, сохранность private metadata после перезапуска и PNG-рендер иконок из скрытых ветвей состояния. Следующая ручная проверка: импортировать сборку, создать и экспортировать оба демо, проверить и преобразовать именно эти скачанные файлы; затем открыть новые копии GDL в GUI Designer. Работа оборудования не проверена.
