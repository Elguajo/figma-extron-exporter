# Состояния кнопок по эталонам — 0.4.2 preview

В 0.4.2 исправлена проверка деталей внутри PNG: координаты и размеры прямоугольников, векторов и растеризуемых подписей могут быть дробными. Их геометрия не округляется. Целочисленными остаются границы самой кнопки и состояния.

## Быстрый процесс

1. Нарисовать кнопку обычной **Group или Frame** непосредственно внутри Frame экрана. Назвать `button_AudioControl` / `btn_AudioControl` либо `feedbackbutton_Power` / `fbtn_Power`. Внутри достаточно фона, текста и графики; отдельные состояния пока не нужны. Названия `Rectangle 11`, `Voice` и `txt_title.place` менять не требуется.
2. Вне экранов, на той же странице Figma, создать группу или Frame **Button Styles**. Внутри два прямоугольника: **Passive / Active**, **Normal / Active** либо **Off / On**. Они автоматически становятся обычным и активным эталонами. Если найдено несколько образцов одной роли, выбрать нужные явно.
3. Другой способ: выделить прямоугольник или готовое состояние существующей кнопки → раздел **«Состояния кнопок»** → **«Выбранное — обычный эталон»**, затем аналогично **«Выбранное — активный эталон»**. Ссылки сохраняются на текущей странице и переживают перезапуск плагина/переименование образцов. Если явный эталон удалён, назначить новый; автоматической подмены нет.
4. Выбрать Frame экрана, секцию проекта или набор экранов через существующий выбор области → **«Создать состояния по эталонам»**.
5. **«Проверить макет» → «Скачать .exui»**. Ключи, роли и свободные ID заполняются обычным механизмом. CLI **0.5.0**, пакет **EXUI/5**, plugin ID и схемы metadata сохраняются.

| Префикс | Создаваемая пара |
|---|---|
| `button_` / `btn_` | **Off / On** |
| `feedbackbutton_` / `fbtn_` | **Normal / Active** |

Off / Normal / Passive используют обычный эталон; On / Active / Feedback — активный. Сохранённый тип кнопки имеет приоритет над последующим переименованием. Дополнительный префикс `button_onoff_` не вводится.

Исходное содержимое оборачивается в первую **Group**. Второе состояние — его копия с оформлением другого эталона. Внешняя Group остаётся Group, Frame остаётся Frame; исходные слои сохраняют свои ID, размеры и координаты. Если фон задан на внешнем Frame, его оформление переносится в Rectangle Background внутри первого состояния, внешний Frame становится прозрачным.

Если есть ровно одно состояние, добавляется недостающая normal/feedback роль; исходное состояние сохраняет оформление и видимость. Готовые кнопки с двумя и более состояниями пропускаются. **Pressed никогда не создаётся автоматически**: его можно добавить вручную в feedbackbutton_ / fbtn_. Обычная button_ по-прежнему содержит ровно два состояния. Кнопки Normal / Pressed и сохранённые прежние схемы не переделываются.

## Изменение оформления

Переносятся заливки, обводки, их цвета/прозрачность, толщина, положение и штриховка. Размеры, текст, иконки, шрифты не заменяются эталоном. Скругление переносится только при включённой настройке **«Применять скругление эталонов»**. Обычный и активный образцы должны визуально различаться.

После изменения образцов выбрать экран и нажать **«Обновить стили состояний»**. Меняется только оформление фона normal/feedback состояний; ручной Pressed, дополнительные состояния, ключи, objectId/controlId/stateId и видимость сохраняются. Повторное создание не дублирует состояния и не обновляет готовые стили молча. Операция создаёт границу Undo; при сбое плагин пытается восстановить прежнее дерево/оформление и сообщает, если откат неполон.

Фон — Rectangle или Frame, совпадающий с областью кнопки. У Frame состояния это может быть собственная заливка. Если подходящих слоёв несколько, выбрать нужный внутри кнопки или состояния и нажать **«Выбранный слой — фон»**. Выбор сохраняется на самом слое и переносится в копии. Повторное нажатие снимает отметку. Несогласованная структура блокируется до изменения первой кнопки.

## Экспорт и границы поддержки

- Group поддерживаются у кнопки и её состояний. Страницы, popup, Slider и другие виды сохраняют свои прежние правила.
- Оформление составного состояния экспортируется в PNG размером с кнопку, включая заливки, обводки, иконки и скругления. Источник не переключается и не перестраивается при экспорте; временные копии удаляются и при ошибке.
- Один верхний непосредственный Text на всю площадь состояния, Arial Regular/Bold, Inter / Inter Display и с поддержанным CENTER / CENTER либо CENTER / BOTTOM сохраняется нативным редактируемым текстом Button. Тексты с другой геометрией, сложным оформлением или несколькими подписями остаются в PNG, чтобы не сдвигать авторский дизайн. В Figma они продолжают редактироваться.
- Одинаковые Inter-подписи, расположенные в отдельном прямоугольнике во всех состояниях, автоматически экспортируются одним редактируемым Label поверх кнопки. Их текст, шрифт, цвет, геометрия и выравнивание должны совпадать. Меняющиеся по состоянию или сложные подписи остаются в PNG. Отдельный Label не получает controlId и не следует за feedback/видимостью кнопки автоматически. [Правила](NATIVE_TEXT.md).
- Прозрачность PNG/скруглений раскрывает однотонный цвет страницы Extron. Произвольный рисунок другого элемента позади кнопки не композируется. Внешняя обводка за границей кнопки обрезается областью PNG; для полного сохранения контура использовать INSIDE.
- Каждое состояние должно совпадать с областью кнопки; координаты/размеры — целые пиксели. Auto layout у неподготовленной внешней кнопки нужно отключить. Изменять число состояний экземпляра компонента следует в его исходном компоненте; готовые экземпляры пропускаются.
- On/Active переключает программа управления Extron. Создание состояний не создаёт команды устройству или автоматическую обратную связь.

Проверки Figma API в тестах моделируются явно. Автоматические тесты и Chromium не подтверждают реальный рендер Figma Desktop, Verify / Save and Build GUI Designer или работу оборудования.
