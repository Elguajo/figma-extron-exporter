# Стандарт подготовки макета Figma → Extron, v1.2

Дата: 19.10.2026. Применяется к плагину 0.1.5 и пакетам `.exui/1`, `.exui/3`, `.exui/4`. Краткая [таблица префиксов с объяснениями](PREFIXES.md).

Этот документ описывает подготовку макета для редактируемых кнопок, подписей, регуляторов и отдельных изображений в GUI Designer. В 1.2 добавлены логотипы/картинки, схема Normal/Pressed и одинаковое распознавание VolumeUp / volumeup; существующие ключи и ID сохраняются.

**Обязательно** — требование поддерживаемого экспорта. **Рекомендуется** — договорённость для удобства команды. При первом распознавании имена определяют назначения; после сохранения приоритет имеют сохранённые типы, ключи и ID. Переименование уже назначенного слоя их не меняет.

## 1. Быстрый порядок работы

1. Создать внешний Frame под нужную панель, задать сплошной цвет фона.
2. Назвать его, например, `Home`; построить слои по схеме ниже, используя префиксы из таблицы.
3. Выбрать внешний Frame и профиль. Нажать **«Распознать по именам»**, проверить таблицу и сообщения, затем **«Сохранить распознанные назначения»**. При ошибках сохранение недоступно, назначения не меняются. Предварительно нажимать «Подготовить выбранный экран» не нужно.
4. Сохранить таблицу ID проекта для программиста. Новым элементам плагин выдаёт ID автоматически; существующие сохраняет. После начала программирования управления эти значения не менять ради оформления.
5. Нажать **«Проверить экран»**, исправить сообщения, затем **«Скачать .exui»**.
6. Проверить пакет через `validate-package`, создать новый `.gdl` через `convert-package`, проверить результат в GUI Designer и выполнить штатный Build.

Практический образец структуры — **«Создать демо для этого профиля»**. У копий из демо нужно заново сохранить назначения скопированных узлов; простое переименование не обновляет их идентичность.

Ручной путь остаётся доступным: «Подготовить выбранный экран», затем «Назначение выбранного элемента» для каждого узла сверху вниз. Он позволяет использовать произвольные имена слоёв и собственные ID.

## 1.1. Имена для автоматического распознавания

| Назначение | Короткое имя | Полное имя | Узел |
|---|---|---|---|
| Экран | `Home` или `scr_Home` | `screen_Home` | Внешний Frame |
| Кнопка | `btn_Music` | `button_Music` | Frame |
| Регулятор | `lvl_Volume` | `level_Volume` | Пустой Frame |
| Подпись | `txt_VolumeValue` | `text_VolumeValue` | Text |
| Логотип | `logo_Company` | `logo_Company` | Frame внутри экрана |
| Статичная картинка | `img_Photo` | `image_Photo` | Frame внутри экрана |
| Иконка в состоянии | `Icon` или `ico_Music` | `icon_Music` | Frame |
| Исходное состояние | `Off` или `Normal` | `state_Off` или `state_Normal` | Frame внутри кнопки |
| Включённое состояние | `On` или `Feedback` | `state_On` или `state_Feedback` | Frame внутри кнопки |
| Удержание, необязательно | `Pressed` | `state_Pressed` | Frame внутри кнопки |

Для состояний также допустим короткий префикс `st_`. Регистр всех частей имени не важен: `btn_volumeup`, `button_VolumeUp` и `BUTTON_VOLUMEUP` равнозначны. После префикса — латинское имя с цифрами и дефисами, без пробелов и `_`; начинать с буквы. Текст, видимый пользователю на кнопке, может быть русским и находится внутри Text.

Контекст задаёт экран: `Home` + `btn_Music` → `home.music`; `Home` + `button_VolumeDown` → `home.volumedown`. Новые ключи используют нижний регистр без автоматической вставки дефисов из CamelCase. Прежние ключи вида `home.volume-down` не переписываются. Одинаковые имена после приведения к нижнему регистру конфликтуют независимо от сокращения префикса, в том числе рядом с уже назначенными слоями. `lvl_Volume` и `txt_Volume` конфликтуют: для подписи использовать `txt_VolumeValue`.

`Off` / `On` — имена **вложенных состояний**, внешний Frame называется `button_Mute`, а не двумя отдельными кнопками. Назначение не означает автоматического программирования переключения устройства.

Имена ресурсов иконок формируются автоматически из ID кнопки и роли, например `assets/control-1-normal.png`. Внутренний ключ иконки включает ключ кнопки и роль; одинаковое имя Icon в разных состояниях не объявляет один общий PNG. Ручное совместное использование ресурса остаётся доступным через форму.

## 2. Экран и структура

| Панель | Размер внешнего Frame | Профиль в плагине |
|---|---|---|
| TLP Pro 1025M | 1280×800 px | TLP Pro 1025M |
| TLP Pro 300M, портрет | 320×480 px | TLP Pro 300M |

**Обязательно:** один экран на пакет; масштабирования нет. На экране от 1 до 64 элементов. Координаты относительно экрана и размеры элементов — целые пиксели, размеры положительные, элементы полностью внутри экрана.

```text
Home                            Frame · Экран
├── button_Music                Frame · Кнопка
│   ├── Off                     Frame · Состояние, normal
│   │   ├── Text                Text · без отдельного назначения
│   │   └── Icon                Frame · PNG-иконка, необязательно
│   ├── On                      Frame · Состояние, feedback
│   │   └── Text                Text · без отдельного назначения
│   └── Pressed                 Frame · необязательное состояние удержания
│       └── Text                Text · без отдельного назначения
├── level_Volume                Frame · Level / Slider
├── btn_VolumeDown              Frame · Кнопка, Normal / Pressed
├── btn_VolumeUp                Frame · Кнопка, Normal / Pressed
├── btn_Mute                    Frame · Кнопка, Off / On
├── text_VolumeValue            Text · Подпись
└── logo_Company                Frame · Статичное изображение
```

Кнопки, подписи, Level и статичные изображения — **непосредственные дочерние узлы экрана**. Промежуточный Frame «Блок громкости», Group или Instance в этом месте не подходит. Визуальный блок можно собрать расположением элементов рядом. Внутри PNG-иконки или логотипа допускается сложная графика: её содержимое экспортируется изображением.

Внешнему Frame нужны назначение «Экран», профиль, имя проекта, ключ и ID объекта. Распознавание выводит ключ страницы из имени (`Home` → `page.home`), задаёт ID страницы `100` и имя проекта из имени Frame. Ручная кнопка подготовки по-прежнему задаёт `page.home` и не назначает содержимое страницы.

## 3. Поля назначения и идентификаторы

| Назначение в форме | Узел Figma | Заполняемые поля |
|---|---|---|
| Экран | Frame | Ключ, ID объекта, имя проекта, профиль |
| Кнопка | Frame | Ключ, ID объекта, ID управления Extron |
| Подпись | Text | Ключ, ID объекта; ID управления не используется |
| Level / Slider | Пустой Frame | Ключ, ID объекта, ID управления Extron |
| Состояние кнопки | Frame внутри кнопки | Роль, имя состояния; ID состояния задаётся по роли |
| PNG-иконка | Frame внутри состояния | Ключ ресурса, файл PNG, имя ресурса Extron |
| Логотип / изображение | Frame внутри экрана | Ключ, ID объекта, файл PNG, имя ресурса Extron; без ID управления |

**Обязательно:**

- Ключ — постоянное обозначение смысла, например `hall.volume`. До 100 символов; латинские строчные буквы и цифры, сегменты через `.` или `-`, первый символ — буква. Пробелы и `_` не допускаются.
- Ключи страницы, элементов и ресурсов уникальны в пакете. Один ресурс можно использовать повторно только с тем же ключом, путём, именем ресурса и одинаковыми PNG-байтами.
- ID объекта страницы: `1..65534`. ID объекта элемента: `1..1000000`, уникален среди элементов экрана. ID страницы и элементов — отдельные пространства.
- ID управления Extron: `1..65535`, уникален среди кнопок и Level экрана. Это адрес для программы управления, а не ID узла Figma. У подписи и изображения ID управления отсутствует (`null` в пакете).
- При переименовании, перемещении, изменении цвета или текста ключ и ID сохраняются. Распознавание не переназначает существующие элементы по новому имени.
- Копии для нового назначения получают новые ключи, ID объекта и ID управления. У копии кнопки нужно также пересохранить назначения её состояний и иконок; идентичный общий ресурс может сохранить свой ключ.

**Рекомендуется:** ключи строить по смыслу `<зона>.<функция>`, например `hall.music`, `hall.volume`, `hall.volume-down`. Слои называть понятно: «Музыка», «Громкость», «Уменьшить». Порядок слоёв и текст подписи не использовать для вычисления ID.

Вести таблицу ID рядом с макетом. Пример для нового проекта; существующие ID ради этой таблицы не перенумеровывать:

| Назначение | Ключ | ID объекта | ID управления | Статус |
|---|---|---|---|---|
| Экран «Главная» | `page.home` | 100 | — | Используется |
| Выбор музыки | `hall.music` | 1 | 8101 | Используется |
| Регулятор громкости | `hall.volume` | 2 | 8102 | Используется |
| Уменьшить | `hall.volume-down` | 3 | 8103 | Используется |
| Увеличить | `hall.volume-up` | 4 | 8104 | Используется |
| Mute | `hall.mute` | 5 | 8105 | Используется |
| Значение громкости | `hall.volume-value` | 6 | — | Используется |

Удалённые назначения оставлять в таблице со статусом «Удалён, ID не использовать». На экране хранится отдельный реестр счётчиков автоматически выданных ID: новый objectId начинается с 1, controlId с 8101, пропуская все более высокие существующие ID. Счётчики растут и сохраняются между запусками, поэтому удалённые автоматически выданные номера повторно не выдаются. Истории удалённых ручных назначений до первого распознавания и реестра удалённых ключей нет. Ручная форма по-прежнему позволяет явно менять ID; это ответственность автора. Для того же интерфейса на другой панели сохранять смысл ключей и ID, отдельно адаптируя геометрию.

## 4. Кнопка

Внешний Frame кнопки задаёт положение и размер. У него нет видимой заливки; фон задают состояния. Внутри — два или три Frame, каждый размером с кнопку и в позиции `x=0, y=0`.

| Роль в форме | ID состояния | Рекомендуемое имя | Назначение |
|---|---|---|---|
| `normal` | 0 | `Off` | Исходный вид |
| `feedback` | 1 | `On` | Вид, который выбирает программа управления |
| `pressed` | 2 | `Pressed` | Вид при удержании кнопки |

**Обязательно:** сохранить назначения после распознавания либо вручную. Одного переименования без сохранения назначений недостаточно. Не добавлять одновременно Off и Normal либо On и Feedback: это дубликаты одной роли. Имена состояний внутри кнопки уникальны. Все имеющиеся виды различаются текстом, цветом фона, цветом текста или изображением; одного изменения выравнивания недостаточно.

Есть три схемы: **Normal/Pressed** для кратковременных команд («+», «−»), **Off/On** для обратной связи устройства без отдельного вида удержания, **Off/On/Pressed** для обратной связи и отдельного вида удержания. У Normal/Pressed жёлтый вид рисуется в Pressed, при отпускании возвращается обычный. Off/On сохраняет два состояния с отключённым press feedback; On выбирается программой управления.

Таблица ID выше описывает canonical metadata ролей в Figma. Для двухсостояниевого Normal/Pressed экспортёр создаёт плотные stateId 0/normal, 1/pressed в пакете/GDL и press=Pressed; canonical metadata pressed/2 на узле не переписывается. Ключи и controlId от этого не меняются.

Наличие Normal/Pressed или статичной картинки выбирает `.exui/4`. Иначе наличие Off/On выбирает `.exui/3`; остальные экраны остаются `.exui/1`. Требуется CLI с соответствующей версией. Старые контракты 1/2/3 не расширялись.

В каждом состоянии:

- Одна непрозрачная сплошная заливка Frame.
- Ровно один Text без отдельного назначения «Подпись». Его рамка занимает всё состояние: `[0, 0, ширина, высота]`.
- Выравнивание Text: горизонтально `CENTER`, вертикально `CENTER` или `BOTTOM`.
- Непустой текст, даже если кнопка содержит иконку. Кнопка только с иконкой и пустым текстом текущему формату не соответствует.
- Один и тот же шрифт, размер и начертание во всех состояниях кнопки.
- Не более одной PNG-иконки.

Для предпросмотра видимо ровно одно состояние. Переключать его можно кнопкой **«Показать состояние»**; экспортируются все имеющиеся состояния. Распознавание не меняет их видимость, геометрию или цвета. Для Mute состояние On может показывать включённое заглушение, но связь с фактическим состоянием устройства задаёт программа управления.

## 5. Текст и оформление

**Обязательно:** Arial Regular или Arial Bold, без смешанных шрифтов/размеров внутри Text. Размер при экспорте: `pt = px × 0,75`; допустимо `4..200 pt`. Например, 24 px в Figma → 18 pt в Extron. Текст и названия — непустые строки до 256 единиц UTF-16. Отключить подчёркивание/зачёркивание и преобразование регистра, letter spacing — 0.

Для самостоятельной подписи Text использовать `LEFT` по горизонтали и `CENTER` по вертикали. Её цвет — одна непрозрачная сплошная заливка текста. Самостоятельная подпись не получает controlId.

У экрана, кнопок, состояний, подписей и Level не должно быть видимых обводок, эффектов, градиентов, масок, прозрачности узла, скруглений, поворота, отражения, skew или prototype interactions. Использовать обычные режимы смешивания `NORMAL` / `PASS_THROUGH`. Элементы должны быть видимы; исключение — состояния кнопки, скрытые для предпросмотра.

Рекомендуется избегать перекрытия интерактивных элементов: фактическое поведение перекрытий на панели отдельно не подтверждено.

## 6. PNG-иконки

Иконка — отдельный Frame с назначением «PNG-иконка» внутри состояния. В него можно поместить векторную графику, скругления или готовое изображение. Прозрачные пиксели PNG допустимы, сам Frame иконки должен быть видимым и иметь opacity 100%.

**Обязательно:**

- Размеры и координаты — целые пиксели. Иконка помещается в кнопку; ширина и высота PNG совпадают с размером её Frame, экспорт 1× Native.
- Горизонтально — строго по центру состояния. Вертикально — сверху (`y=0`) или по центру. Учитывать, что разница размеров кнопки и иконки должна позволять целые координаты.
- Ключ, например `icon.music-normal`.
- Файл в пакете, например `assets/music-normal.png`: имя до 64 символов без расширения, только строчные латинские буквы, цифры и дефисы; первый символ — буква или цифра.
- Имя ресурса Extron, например `exui-music-normal.png`: ASCII, первый символ — буква или цифра, далее буквы, цифры, `.`, `_`, `-`; до 100 символов с `.png`. Имена ресурсов уникальны без учёта регистра.
- До 16 различных PNG на экран, каждый до 4 MiB и до 4096×4096 px. Общий размер распакованного пакета — до 16 MiB.

PNG-иконка является ресурсом состояния кнопки. Для отдельной картинки использовать `logo_` или `img_` / `image_`, как описано ниже. Автоматическая растеризация интерактивных кнопок не выполняется.

## 6.1. Логотипы и отдельные изображения

Frame `logo_Company`, `img_Photo` или `image_Photo` находится прямо в экране. Распознаётся как graphic, получает objectId и PNG-ресурс, controlId=null. В GDL создаётся отдельный нативный PBImage, без текста, состояний и поведения кнопки. Внутренняя графика логотипа растрируется; положение и ресурс изображения остаются редактируемыми.

Внешний Frame имеет целую геометрию, без поворота/эффектов/обводок/скруглений, видим, opacity 100%. Для прозрачного фона убрать заливку внешнего Frame; прозрачные пиксели PNG поддерживаются. Внутри Frame можно размещать векторы, текст и другую графику. PNG экспортируется 1×, включая прозрачные поля, и должен точно совпасть с размером Frame. При нажатии ничего не происходит; для кликабельного логотипа нужна button_ со состояниями и иконкой.

Иконки и изображения используют общий лимит 16 PNG. Изображение может занимать большую часть экрана, но не заменяет назначение «Экран» и не превращает нарисованные внутри кнопки в интерактивные объекты.

## 7. Блок громкости

Регулятор громкости — пустой Frame с назначением **Level / Slider**, одной непрозрачной SOLID-заливкой и собственными ключом/ID. Экспортируется горизонтальный PBLevel в режиме Slider, слева направо, диапазон `0..100`. Внутрь Frame нельзя добавлять бегунок, полосу заполнения, текст или другие слои.

Для блока с «−», «+», Mute и «42%» использовать отдельные элементы из таблицы ID выше. Все они находятся непосредственно в экране. Цифра «42%» экспортируется статическим текстом; текущая модель не описывает динамическую привязку этой подписи к Level.

Имена функций: `btn_VolumeUp` / `button_VolumeUp` — «+»; `btn_VolumeDown` / `button_VolumeDown` — «−»; `btn_Mute` / `button_Mute` — заглушение. Для нескольких зон: `button_HallVolumeUp`, `button_TerraceVolumeUp`. Рекомендуемые состояния для «+»/«−» — Normal/Pressed, для Mute — Off/On с необязательным Pressed. Цвет Pressed задаёт дизайнер; плагин не перекрашивает его по имени.

Изменение реальной громкости, обработка кнопок, Mute и обратная связь устройства требуют программы управления Extron. Плагин экспортирует элементы и их ID, но не создаёт эту программу и не гарантирует возможность адресовать Label как динамическое поле.

Кастомный бегунок, скруглённая дорожка, несколько слоёв заполнения, вертикальный регулятор и другой диапазон пока не входят в этот стандарт, поскольку текущий экспортёр их не поддерживает. Состояния normal / feedback / pressed относятся к кнопкам; три позиции ползунка 0% / 50% / 100% не заменяют модель Level.

## 8. Проверка перед передачей

- [ ] Внешний Frame точно соответствует выбранному профилю; назначение «Экран» сохранено.
- [ ] На экране 1..64 непосредственных элемента: кнопки, подписи, Level и статичные изображения.
- [ ] Координаты и размеры целые, все элементы внутри экрана.
- [ ] Ключи и ID заполнены, нет дубликатов, таблица проекта актуальна.
- [ ] У каждой кнопки выбрана одна схема: Normal/Pressed, Off/On или Off/On/Pressed; назначения сохранены, геометрия, Text и различия соответствуют разделу 4.
- [ ] Подписи и шрифты соответствуют разделу 5; неподдерживаемого оформления нет.
- [ ] Level — пустой Frame; иконки подготовлены по разделу 6.
- [ ] У скопированных узлов пересохранены назначения; новых назначений со старыми ID нет.
- [ ] «Проверить экран» завершается успешно, затем скачан `.exui` без ошибки PNG. Во время экспорта макет не редактируется.
- [ ] Пакет прошёл `validate-package`; новый `.gdl` создан и отдельно проверен в GUI Designer, включая состояния, редактируемость и Build.

«Проверить экран» проверяет структуру и свойства, но не выполняет всю проверку PNG. Успешное скачивание не заменяет проверку CLI, GUI Designer и испытание программы управления с устройством. Повторная конвертация создаёт новый GDL и не сохраняет ручные правки предыдущего.

## 9. Поддержка и изменение стандарта

Поддерживается распознавание по соглашению об именах. Произвольный макет без префиксов и структуры автоматически не распознаётся. Не поддерживаются Figma variants/instances, промежуточные группы контролов, несколько экранов в одном экспорте плагина, навигация и пользовательские popup. Возможности CLI `.exui/2` не означают, что плагин уже умеет их создавать.

При расширении экспортёра этот документ обновляется вместе с проверками. Новые возможности становятся обязательными правилами только после реализации и проверки; текущие ограничения нельзя обходить одним переименованием слоёв.
