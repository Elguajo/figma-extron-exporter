# Плагин 0.7.0 — связь popup по имени и чистые углы кнопок

Совместимый CLI: **0.7.0**, контракт **EXUI/5**. Выпускаются вместе.

## Обновление 0.7.0: оформление существующего Pressed

При выборе «Применить новый стиль и к готовым» Normal / Off получает обычный образец, On / Active и существующий Pressed — активный. Это работает и для пары Normal / Pressed, и для тройки Normal / Active / Pressed. Имена, роли, ID, геометрия и видимость сохраняются. При пропуске готовых кнопок Pressed сохраняет прежнее оформление. Само состояние Pressed по-прежнему добавляется вручную. [Проверки](../../../docs/verification/results/2026-10-23-pressed-button-styles.md).

## Обновление 0.7.0: контраст текста и иконок

В «Оформление кнопок» добавлена включённая по умолчанию настройка **«Исправлять контраст текста и иконок»**. При применении образцов недостаточно контрастные однотонные заливки и обводки становятся чёрными или белыми: например, белый Input 7 и золотая иконка на золотом фоне станут чёрными. Проверка выполняется отдельно для каждого изменённого состояния; контрастные цвета сохраняются. Для уже подготовленных кнопок выберите **«Применить новый стиль и к готовым»**. Сложные заливки, изображения и другие неподдержанные участки отмечаются для ручной проверки. Настройку можно отключить. [Подробные правила](../../../src/figma-plugin/BUTTON_STATES.md#контраст-при-применении-оформления).

## Обновление 0.7.0: оформление выделенного popup

Исправлена ситуация «Оформление применено; кнопок: 29; новых состояний: 0», когда выделен другой popup или группа без состояний. Сохранённый режим экспорта проекта больше не подменяет область оформления: выделите `popup_`, `modalpopup_`, `popupgroup_` либо дочерний слой popup — команда обработает этот контейнер. Настройки и состав экспортируемого проекта сохраняются.

В результате показаны имя области, число подготовленных кнопок, обновлённых готовых кнопок и новых состояний. Если изменений нет, плагин пишет это явно. При обновлении готовых кнопок существующий Pressed получает активный образец; при пропуске его оформление сохраняется. Номер версии по запросу пользователя остаётся **0.7.0**; для обновления замените файлы старой сборки и перезапустите плагин.

[Проверки обновления](../../../docs/verification/results/2026-10-23-popup-button-style-scope.md): typecheck, 515 тестов, build, Chromium и 26 проверок JS из готового архива. На исходном пользовательском макете новая сборка ещё не запускалась.

## Полупрозрачный текст — понятная ошибка

Цвет нативного текста — любой непрозрачный `#RRGGBB`. Если у текста непрозрачность заливки или Opacity слоя ниже 100%, проверка останавливается на этом слое: «полупрозрачный текст не поддерживается. Поставьте 100% непрозрачность заливки текста и слоя». Раньше подпись с полупрозрачной заливкой могла молча стать PNG. Альфа цвета текста не экспортируется: GUI Designer её хранит, но вид на панели и в GCP не проверен. Шрифты для нативного текста прежние: Arial Regular/Bold, Inter и Inter Display.

## Закруглённые кнопки без белых углов

Если фон страницы задан изображением (`image_Background`), а у Frame экрана осталась белая заливка, в GUI Designer и GCP у закруглённых кнопок были видны белые углы. Состояния кнопок с PNG теперь экспортируются с прозрачной заливкой `#00000000`. В скруглениях и прозрачных участках PNG виден настоящий фон под кнопкой. Обычные кнопки с нативным цветом не изменились. Чтобы исправить существующий GDL, экспортируйте макет заново и сконвертируйте его.

## Связь popup и групп по имени

При первом распознавании `popupref_WallLayouts` автоматически связывается с `popupgroup_WallLayouts`; `popupref_Sources` — с `popup_Sources`. Сравнивается часть имени после префикса без учёта регистра. Короткие префиксы `pr_`, `pgrp_`, `pop_` тоже работают. Точки и дефисы различаются. Используется фактический ключ цели, включая заданный вручную.

Цель должна быть соседним контейнером в том же проекте или секции. В режимах «Выбранные фреймы» и «Текущая страница» новое место находит совпадающий popup/группу без предварительного ручного связывания. Несвязанные макеты и цели других проектов не добавляются. В режиме одного выделения выберите секцию или Frame `project_…`, содержащие экран и его popup.

Если совпадений несколько, например `popup_WallLayouts` и `popupgroup_WallLayouts`, экспорт останавливается с указанием конкретного popupref. Выберите его → «Содержимое места popup» → нужная цель → «Сохранить связь popup». При полном экспорте проекта каждому оставшемуся обычному popup тоже необходимо место на странице.

Сохранённые связи (включая отсутствующую цель и явно снятую связь), ID и назначения Extron Kit не заменяются. Старое место без связи нужно один раз связать через список. Размер места должен совпадать с размерами всех popup группы. Модальные popup и отдельные участники группы не становятся прямыми целями.

## Установка

Распакуйте `figma-extron-plugin-0.7.0.zip` в постоянную папку. В Figma Desktop: Plugins → Development → Import plugin from manifest… → `manifest.json`. Перезапустите плагин и проверьте версию **0.7.0**. Для development-плагина из репозитория достаточно перезапуска после сборки. ID плагина остаётся прежним.

Конвертируйте новым CLI 0.7.0 ([заметки](../../cli/0.7.0/README.md)): он также исправляет пустой preview страниц в GCP.
