# Контракт `.exui/4`: отдельные изображения и Normal/Pressed

Принят 19.10.2026 для плагина 0.1.5. Основа — одностраничный [exui/3](exui-v3.md). Старые v1/v2/v3 не меняются. Несколько страниц и popup из v2 в этот контракт не входят.

Маркеры: manifest `exui/4`, screen `exui-screen/4`; [manifest schema](../schemas/exui-v4/manifest.schema.json), [screen schema](../schemas/exui-v4/screen.schema.json). ZIP, профили, целостность, limits, текст, геометрия и общие поля соответствуют v1/v3.

## Статичное изображение

Новый элемент `kind: "graphic"` содержит только общие `key`, `objectId`, `controlId: null`, `name`, `rect` и `image` — ключ PNG в assets. PNG обязателен, размер равен ширине/высоте rect (Native 1×). Text/font/states/press, диапазон Level, навигация и controlId не допускаются.

В GDL writer клонирует PBImage из закреплённого донора, устанавливает userId=0, ресурс buttonImage, layout Native (3), MiddleCenter (3), без формы, текста, заливки и обводки. PNG может содержать alpha. Новый объект остаётся отдельным PBImage; внутренние детали PNG не становятся отдельными редактируемыми векторами.

Независимый reader проверяет тип, objectId, userId, ключ, имя, геометрию, ссылку на ресурс, layout/alignment и отсутствие состояний/текста/фона/формы. Ресурсы картинок и иконок делят общие limits и проверку CRC/SHA.

Донор берётся из уже закреплённого PBImage Image1 в popup Confirmation. Реестр получил необязательный `elements.graphic`; исходные файлы и SHA доноров не менялись. Текущий CLI со старым реестром без этого указателя позволяет генерировать прежние типы, а изображение отклоняет с donor-element. Старый CLI с новым реестром может отклонить неизвестное поле graphic: CLI и реестр следует обновлять вместе.

## Кнопка кратковременной команды

Добавлена пара явных stateId/role **0/normal + 1/pressed**, с обязательным `press`, указывающим имя pressed. Writer создаёт два состояния с ID/индексами 0/1, default state 0, press feedback 1. При удержании отображается pressed; схема не задаёт AV-команду, шаг громкости или повтор.

Сохраняются варианты v3: normal/0 + feedback/1 без press (press feedback -1), а также normal/0 + feedback/1 + pressed/2 с press. Роли/ID/ссылка проверяются вместе; несовпадения, пропущенный press у momentary, дубликаты и одинаковые виды отклоняются.

Приватные metadata плагина сохраняют canonical role IDs normal=0, feedback=1, pressed=2. Только при упаковке пары Normal/Pressed выполняется явная проекция pressed/2 → stateId 1, при сохранении controlId и ключей. Для тройки состояние pressed остаётся 2. Результат в пакете уже содержит точные плотные IDs; reader не угадывает их по именам.

## Выбор версии и совместимость

Плагин выбирает v4, если есть graphic или Normal/Pressed. Иначе при наличии Off/On — v3, остальные экраны — v1. На одном экране могут находиться все три схемы кнопок и изображения. Старый CLI v1/v2/v3 откажет по неизвестной версии v4; нужен обновлённый CLI.

Существующие metadata и числовые ID не перезаписываются. С версии 0.1.5 новые имена формируют lowercase ключ без CamelCase-дефисов, поэтому VolumeUp и volumeup равнозначны. Прежние ключи сохраняются, проверка одинаковых имён работает и рядом с ними.

Тесты используют fake Figma API для создания дерева и PNG, настоящие CLI/x86 Extron writer и независимый NRBF reader для конвертации. Ручная Figma, GUI Designer/Build и оборудование подтверждаются отдельно.
