# Распознавание имён Figma — границы и совместимость

19.10.2026. Реализация 0.1.4 по согласованной схеме: внешний Frame Home, короткие/полные префиксы, состояния Off/On с необязательным Pressed. Пользовательское руководство: [стандарт v1.1](../src/figma-plugin/AUTHORING_STANDARD.md).

## Решение и влияние

UI → dry-run `recognize()` → таблица с новыми/существующими назначениями → отдельное `applyRecognition()` → прежний capture/export/ZIP. Распознавание сохраняет только metadata и резерв ID; не меняет имена, оформление, геометрию, родителей или видимость. Предлагаемые metadata проверяются тем же capture через локальный reader, без временной записи в документ.

Затронуты только Figma producer, выбор версии пакета и чтение новой версии CLI. Extron adapter и независимый verifier переиспользуются. Ручная форма и прежние демо сохранены. Новых зависимостей и сетевых сервисов нет.

Риск: MEDIUM — автоматическое назначение постоянных ID и новый вариант кнопки. Главный инвариант: существующие назначения не перезаписываются; непроверенный или изменённый план не применяется; правила exui/1 и exui/2 не расширяются.

## Хранение и переход

- Metadata узла остаются `exui-node/1`, ключ `exui`. Существующие корректные записи используются без перезаписи и имеют приоритет над именем слоя. Повреждённые и скопированные metadata блокируют распознавание.
- Новая отдельная запись на экране `exui-id-registry`: `{schema:"exui-id-registry/1", ownerNodeId, nextObjectId, nextControlId}`. Отсутствие записи — обычный старый документ; счётчики инициализируются с 1/8101 и поднимаются выше всех активных ID. Некорректная/неизвестная запись не сбрасывается автоматически.
- Повторный запуск с тем же документом сохраняет назначения. Удалённые автоматически выданные ID остаются ниже счётчиков и повторно не выдаются. Полной истории удалённых ручных ID/ключей нет. Новая подготовка экрана не обещает соответствия ID другому независимо подготовленному экрану панели.
- План хранится только в памяти плагина, привязан к экрану, профилю, token и подписи свойств/metadata/реестра. Смена выделения, другая команда, повторное применение или изменение документа требуют нового отчёта.
- Перед записью узлов сначала сохраняется резерв ID. При ошибке делается попытка восстановить все исходные записи. Если восстановление полное, восстанавливается и прежний реестр; иначе резерв остаётся, ошибка явно сообщает о частичном восстановлении. При аварийном завершении возможны пропуски и частично сохранённые назначения; повторный анализ сохраняет уже записанные ID. Атомарность между записями Figma не заявляется.
- Старый плагин игнорирует отдельный реестр; он по-прежнему понимает metadata/1 для трёхсостояниевых кнопок. Двухсостояниевые кнопки ему не поддержаны. Ручное изменение ID при работе старой или новой версией требует контроля автора.

## Версии пакета

При наличии хотя бы одной двухсостояниевой кнопки producer выбирает exui/3, иначе сохраняет exui/1. Для новой версии применяется схема на базе одностраничной v1, с двумя состояниями normal/feedback и без press либо с прежними тремя состояниями и ссылкой на pressed. Понижение версии и изменение смысла старых пакетов не выполняются. Подробности: [exui-v3](exui-v3.md).

Основание значения press=-1: независимое чтение исходного Full-Test-Project показывает его у Main Volume Up/Down/Mute и других двухсостояниевых кнопок. Подтверждение новой генерации и граница GUI-проверки — в протоколе реализации.

## Проверки и ограничения

Поведение защищено тестами распознавания алиасов, нормализации ключей, двух/трёх/смешанных состояний, legacy metadata, выделения/token/restart, отсутствия записей при ошибках, восстановления и частичного отказа, монотонности ID, повреждённого реестра и копий. CLI отдельно проверяет новую версию, состояния/press и сохранение строгости прежних контрактов. Chromium проверяет предварительный отчёт, клавиатуру, запрет сохранения ошибок, сброс профиля и прежние downloads/bridge.

Настоящие Figma и оборудование не моделируются как пройденные проверки. Ручная подготовка структуры и совместимого оформления остаётся обязательной. Копия уже назначенной кнопки требует явного переназначения; копия ещё неназначенного дерева может быть распознана после изменения его имени на уникальное.
