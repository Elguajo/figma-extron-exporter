## Объём и критерии

| Возможность | Результат | Проверка |

| Динамическое значение | PBLabel с управляющим ID и dynamicText | ID и текст проверяются независимо |
| Индикаторы | Режимы PBLevel: Gauge, MultistateLevel, VolumeLED | Режим и диапазон |
| Фигуры, линии, дата/время | PBShape, PBLine, PBDateTime | Нативный тип и свойства |
| Несколько страниц, popup, modal, popup-reference | Плагин создаёт контейнерный пакет | CLI проверяет все связи и ID |
| Состояния и поведение | Несколько feedback-состояний; информация о группах выбора, видимости и доступности | Разделять оформление и логику программы управления |
| Динамические картинки, видео | Учитывать возможности платформы | Явный отказ для неподдерживаемых 1025M/300M, без фиктивной поддержки |

Новые короткие и полные префиксы регистронезависимы. Перед сохранением — таблица предложенных назначений. Экспорт не меняет макет. Старые metadata и exui/1–4 читаются по прежним правилам. Новая версия контракта exui/5; старый CLI вправе её отклонить. Управление оборудованием, переходы и обновление feedback выполняет программа Extron, а не Figma-плагин.

## Архитектура и совместимость

Поток: распознавание → проверяемый план metadata/ID → capture → exui/5 → строгая схема/нормализация → локальный x86 writer → независимое NRBF-чтение → публикация нового GDL.

Риск HIGH: новый публичный контракт затрагивает producer, reader, writer и verifier. Основной инвариант: ни один новый тип не превращается молча в другой объект и неподдерживаемые свойства не теряются. Старые схемы и эталонные доноры не расширяются задним числом. Доступные в существующих закреплённых донорах PBLine (Main), PBDateTime (Start), PBShape (Offline Page) переиспользуются. У PBSlider в библиотеке 1.28.0.7 есть независимый параметрический конструктор без FormMain; он проверен отдельно исследовательским вызовом. Его применение требует инициализации общих полей из клона существующего контрола и независимой проверки результата; успешный вызов конструктора сам по себе не доказывает GUI-совместимость.

Переноса/перезаписи старых metadata нет. При появлении новых полей их обработка версионируется; старый плагин не считается совместимым с новыми назначениями. Ошибки записи/устаревшие планы должны сохранять прежние гарантии восстановления и резерва ID.
