# Контракт `.exui/3`: один экран и необязательное состояние удержания

Логотипы и другая пара состояний Normal/Pressed добавлены отдельно в [exui/4](exui-v4.md). Правила v3 ниже сохранены.

Принят 19.10.2026 для кнопок Off/On из Figma-плагина 0.1.4. Контракт основан на одностраничном [`.exui/1`](exui-v1.md); возможности нескольких страниц и popup из `.exui/2` в него не входят. Версии 1 и 2 сохраняют прежние строгие требования.

Состав ZIP, профили, limits, поля страницы/элементов/ресурсов и проверки целостности совпадают с версией 1. Маркеры обязательны: manifest `schema: "exui/3"`, screen `schema: "exui-screen/3"`. Схемы: [manifest](../schemas/exui-v3/manifest.schema.json), [screen](../schemas/exui-v3/screen.schema.json). Пакет с несовпадающими версиями отклоняется.

Единственное смысловое расширение — кнопка может содержать два или три состояния:

| Вариант | Явные stateId / role | Поле press | Результат GDL |
|---|---|---|---|
| Off/On | 0 / normal, 1 / feedback | Отсутствует | Ровно два состояния, TLPPressFeedbackStateID = -1 |
| Off/On/Pressed | 0 / normal, 1 / feedback, 2 / pressed | Обязательное имя состояния pressed | Три состояния, press feedback = 2 |

Имена не определяют роль внутри пакета: `name` может быть Off/On, Normal/Feedback или другим уникальным непустым именем. Роли и stateId заданы явно, входной порядок сортируется. Имена Off/On являются соглашением Figma producer. Каждый вид обязан различаться текстом, цветом или изображением; выравнивания недостаточно. Остальные ограничения кнопок сохранены.

У двухсостояниевой кнопки `press` нельзя заменять `null`, связывать с On или Off. Третье искусственное состояние не добавляется. Off — начальный вид, On выбирает внешняя программа управления; отдельной press-анимации нет. Переключение, AV-команды и драйверы не создаются.

Значение -1 наблюдается у исходных двухсостояниевых PBButton проекта Full-Test-Project. Его запись использует существующий Extron adapter; count/ID/состояния и press feedback проверяются независимым NRBF reader. Результат автоматического writer не заменяет ручной проверки в GUI Designer и на оборудовании.

Плагин выбирает `.exui/3`, если на экране есть хотя бы одна кнопка без Pressed. Остальные кнопки на том же экране могут иметь три состояния. Когда все кнопки трёхсостояниевые либо кнопок нет, сохраняется `.exui/1`. Идентификаторы при смене версии не меняются.

Для конвертации нужен обновлённый CLI; старый CLI откажет по неизвестному маркеру, автоматического понижения версии нет. Команды прежние: `validate-package`, `convert-package`, `id-map`. Пересобрать решение перед конвертацией нового пакета.
