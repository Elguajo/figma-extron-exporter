# Технические решения

## D001 — первый срез на C#/.NET

Статус: принято для инструментов чтения и пересборки контейнера, 19.10.2026.

Использовать C#/.NET 10 и официальный Microsoft NRBF decoder. Причина: для чтения сложного графа уже существует подходящая библиотека; свой NRBF-парсер сейчас увеличил бы объём неподтверждённого кода. Собственный код ограничен обнаруженным KP-контейнером и анализом записей.

Пакет decoder не является writer. Собственная запись новых/изменённых записей остаётся отдельной исследовательской задачей. Наличие Microsoft decoder не доказывает возможность сериализовать проект Extron без его внутренних правил.

TypeScript остаётся запланированным языком Figma-плагина. Ядро не зависит от Figma или desktop UI. Ядро (`src/extron`, `src/screen`) DLL Extron не использует; отдельная граница для записи — D006.

## D002 — исследовательские образцы вне Git

Пользовательский GDL и ресурсы третьей стороны хранятся локально; в репозитории остаются манифест, хеши и инструкции. Результаты генерации и приватный SDK также исключены. По запросу пользователя репозиторий связан с https://github.com/Elguajo/figma-extron-exporter; исходный код, документация, тесты и протоколы сохраняются в GitHub.

## D003 — не заявлять GUI-совместимость по проверкам контейнера

Успешные тесты отделены от штатного открытия, Verify, Build и проверки устройства. Эти уровни отмечаются разными статусами в протоколе. Первое ограничение модального диалога обойдено открытием через Проводник; GUI-проверка обоих вариантов выполнена, устройство не проверялось.

## D004 — ограниченный редактор существующей подписи

Принято для эксперимента 19.10.2026. Использовать Microsoft decoder для выбора одной PBButton по уникальному UInt16 ID, проверки состояний и владения строками. Менять только LengthPrefixedString существующих BinaryObjectString, сохраняя ObjectId и остальные байты; повторно декодировать и сравнивать поля до записи нового файла. Общие с другими объектами строки/состояния, formatted text, неизвестные массивы, ненулевой checksum и иные версии отклонять. Это существенно меньше полного NRBF writer; новые объекты этим методом не создаются.

## D005 — Build принадлежит GUI Designer

Уточнено пользователем 19.10.2026: экспортёр выдаёт редактируемый `.gdl`; пользователь выполняет Build в GUI Designer. Экспортёр не вызывает редактор и не реализует сборку панели. Save and Build в исследовательской проверке подтверждает совместимость артефакта. Многозаписный GDL после штатной сборки с 19.10.2026 читается структурно (D009); Build по-прежнему не переносится в экспортёр и не автоматизируется.

## D006 — экспериментальный локальный адаптер к установленному GUI Designer

Принято для этапа 4, 19.10.2026. Новые объекты создаются не собственным NRBF writer, а внутренними классами Extron. Порядок:
1. Отдельный процесс `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe` (x86, Windows PowerShell 5.1) загружает сборки из установленного GUI Designer 1.28.0.7.
2. Процесс десериализует payload донора.
3. Нужные объекты клонируются через BinaryFormatter.
4. Backing fields записываются через reflection.
5. Смена панели выполняется только через фабрику Extron `PBPlatformPro.CreatePlatform`.
6. Новый ProjectGCP передаётся обратно.

Хост: `src/adapter/host/ExtronAdapterHost.ps1`; граница процесса: `src/adapter` (`ExtronAdapter`). Наш процесс .NET 10 не загружает x86-сборки и не использует BinaryFormatter.

Каждый результат до записи проверяется независимо: Microsoft NRBF reader читает его без Extron (`ScreenVerifier`, `BoundsChecks`). Упаковку выполняет наш структурный контейнер. Библиотеки Extron остаются частью установленного приложения и в нашу поставку не входят.

Причина выбора: проверка на установке подтвердила загрузку сборок, клонирование, запись полей, фабрику платформы и детерминированное сохранение. Независимый writer графа Extron потребовал бы существенно больше неподтверждённого кода.

Ограничения:
- зависимость от Windows, x86 PowerShell 5.1 и версии 1.28.0.7;
- внутренние классы не являются публичным SDK.

Независимый writer остаётся предпочтительной альтернативой, если адаптер не пройдёт GUI-проверку или будет неприемлем по условиям Extron. Результат для TLP Pro 1025M и 300M прошёл ручной цикл GUI Designer: открытие, редактирование, Verify, Save and Build, повторное открытие (протокол `verification/results/2026-10-19-first-screen.md`). Работа на панели не проверена.

## D007 — десериализация через Extron только для доноров из реестра

Принято 19.10.2026. BinaryFormatter десериализует только payload из `samples/donors.json`. Каждый такой донор:
- закреплён SHA-256;
- получен командой `prepare-donor` из неизменяемого эталона, указанного в `samples/manifest.json` с его SHA-256.

CLI принимает id донора, а не путь. Хост повторно сверяет SHA-256 payload перед десериализацией. Произвольный внешний GDL в этот механизм не попадает; его можно только читать NRBF reader (`inspect`, `list-controls`).

Доноры и результаты хранятся вне Git. Реестр, хеши и команды подготовки хранятся в Git.

Профиль панели определяется донором, а не названием в JSON. Генератор:
- сверяет `panel` описания с донором;
- сверяет фактический класс платформы, part number и размер с реестром;
- проверяет числовое значение enum по типам Extron.

## D008 — экспериментальное описание экрана, не контракт .exui

Принято 19.10.2026. `exui-screen-experiment/0` (`src/screen`) описывает одну страницу: button, label, level и PNG-ресурсы. Неизвестные поля JSON отклоняются.

Различаются три идентификатора:
- `key` — семантический ключ; записывается в Comments как `exui-key=`;
- `objectId` — editor `idField`, уникален на странице;
- `controlId` — `userIdField`, ID Extron, уникален в описании.

Все три берутся из описания. Генератор не выводит их из порядка, текста или координат; это проверено тестом.

Роли состояний кнопки:
- `normal` — состояние 0;
- `pressed` — press feedback;
- `feedback` — состояние, которое включает программа управления.

Нажатие не смешивается с выбором источника. AV-логика не назначается. На момент D008 схема `.exui` ещё не была зафиксирована; минимальный контракт этапа 5 позднее принят в D011.

## D009 — структурное чтение многозаписного контейнера

Принято 19.10.2026. Reader принимает до 16 записей; ProjectGCP должна быть первой. Для каждой записи проверяются:
- последовательное расположение без промежутков и перекрытий;
- согласие локального и центрального заголовков;
- простое ASCII-имя без пути и повторов;
- размеры и CRC32 после распаковки.

Пересборка копирует остальные записи побайтно и пересчитывает смещения. Глобальная замена байтов KP/PK не используется.

Доноры обязаны быть несобранными однозаписными проектами. Чтение собранного файла нужно, чтобы проверять ID после ручного Save and Build.

## D010 — использование extron-gdl-toolkit

19.10.2026. В публичном репозитории toolkit (commit `4390741`) общая LICENSE не найдена. Пользователь сообщил, что лицензия у нас есть, и разрешил использовать необходимое. Текст и условия лицензии в репозиторий не переданы; при распространении их нужно приложить.

Фактически файлы toolkit не копировались. Приёмы реализованы заново и проверены на нашей установке:
- x86-хост;
- AssemblyResolve только из предзагруженных сборок;
- clone-never-construct;
- запись backing fields;
- `CreatePlatform`;
- обход ловушек `PBStates`/`mItems` и одноэлементных списков PowerShell.

Источник указан в заголовке хоста и в протоколе. Seeds, шрифты и прочие ресурсы toolkit не загружались и не используются.

## D011 — минимальный версионируемый ZIP-контракт `.exui/1`

Принято 19.10.2026 после GUI-рубежа этапа 4. Пакет содержит manifest, одну screen и объявленные PNG. Новые CLI: `validate-package` без Extron и `convert-package`. JSON Schema 2020-12 встроены в `src/screen`; evaluator ограничен использованным подмножеством. Библиотек/сервисов в runtime не добавлено. Reader проверяет строгую форму и целостность, затем понижает контракт до существующего `GeneratePlan`; запись и независимый verifier переиспользуются. Экспериментальный вход D008 продолжает работать; пакет не меняет формат экспериментального JSON.

Версия 1 поддерживает только доказанное подмножество двух профилей: одна страница, button/label/PBLevel Slider слева направо 0..100, Arial и непрозрачные цвета, PNG в состояниях. Новые возможности потребуют отдельного доказательства и версии. Отдельный bindings-файл не нужен: key/objectId/controlId находятся вместе в screen. У состояний явные stateId 0/normal, 1/feedback, 2/pressed, входной порядок роли не меняет. Реестр исторических ID и merge ручных правок отсутствуют. Семантические ID задаёт producer; отсутствие оборудования работу над контрактом не блокирует.

ZIP — внешний ввод, но Extron десериализует по-прежнему только закреплённый донор D007. Пакет не задаёт donor/DLL/host paths. Лимиты ZIP/JSON/PNG, отказ неизвестных полей/версий, duplicate JSON, безопасные имена, CRC и SHA обеспечиваются до хоста. Результат публикуется после независимой проверки; рядом пишется report без перезаписи. При штатном отказе конечные файлы не остаются; авария ОС между публикацией GDL и report не является транзакционной.

Подтверждено автоматически для обеих панелей: пакетный GDL побайтово совпадает с прежним генератором, повторяем, значимые данные и явные ID сохраняются после перестановки, изменения текста и координат. Новый ручной GUI-цикл пакетных файлов не выполнен; предыдущие экраны прошли GUI Designer, Verify counts не переданы. Устройство не проверено. Полный контракт: `exui-v1.md`; протокол: `../verification/results/2026-10-19-exui-v1.md`.

## D012 — `.exui/2`: страницы, popup, группы и указание навигации

Принято 19.10.2026 по запросу пользователя. Это новая версия; смысл v1 не меняется. Reader выбирает версию только по `manifest.schema`.

В версию 2 входят:
- несколько страниц;
- обычные popup (свой размер, прямая ссылка или группа) и модальные popup (полный холст, без группы);
- реестр групп;
- элемент `popup-ref` на страницах;
- поле `navigate` у кнопок.

Основания:
- Прямая привязка обычного popup без группы найдена в нашем эталоне.
- Ссылки на модальные popup Build создаёт сам; это проверено на собранном Full-Test-Project. Поэтому автор их не задаёт.
- Связь popup пишется во всех четырёх местах из одного плана и проверяется независимо, включая точный набор обратных ссылок.

`navigate` в GDL не записывается. В GUI Designer 1.28 действия кнопок (`PanelBuilder.PBAction*`) остались только как типы сборки и в проектах не встречаются. Переходы — работа программы управления: она открывает страницы и popup по имени. `navigate` питает:
- карту ID (`id-map`);
- проверку достижимости: каждая страница или popup с `shownBy: "navigation"` должны иметь кнопку, которая к ним ведёт.

`PBControlGroup` создаётся конструктором `(name, id)`. Клонировать не из чего: реестр эталона пуст. Сам объект — сериализуемые данные без ссылок на редактор.

GUI-совместимость `exui/2` подтверждается отдельной ручной проверкой (`../verification/results/2026-10-19-pages-popups.md`). Контракт: `exui-v2.md`.

## D013 — доноры v2 и сравнение графов

Принято 19.10.2026. Доноры дополнены страницей Start со ссылкой «Volume Level», обычным popup «Volume Level» и модальным «Confirmation» — источниками клонирования для popup.

Для 1025M popup меньше холста масштабируются вместе с содержимым. Прежние доноры сохранены локально в `samples/donors/v1/`; реестр закрепляет новые SHA.

Одностраничный результат на донорах v2 побайтово отличается, но граф объектов NRBF равен, кроме `List<T>._version`. Это счётчик изменений .NET без значения для проекта. По той же причине генератор не трогает пустые списки: `Clear()` увеличивает `_version`.

Команда `compare-graph` (`NrbfGraph`):
- сравнивает графы от корня без учёта ID записей;
- отдельно показывает различия без `_version`.

Это основной инструмент регрессии, когда побайтовое сравнение неприменимо.

## D014 — MVP Figma-плагина как отдельный producer `.exui/1`

19.10.2026, ветка `codex/figma-plugin`, отдельная рабочая копия от `6a006f5`, поскольку основная папка содержит параллельные изменения ядра/доноров. Плагин не меняет схемы, C#-генератор, адаптер или исходные образцы.

Выбор: компактный TypeScript-плагин с подготовленными Frame, тремя Frame состояний, Text и явными raster icon Frame. Имена слоёв не определяют роли/ID. Metadata `exui-node/1` в private pluginData хранит semantic key, objectId/controlId и ownerNodeId, у состояния — role/stateId/stateName. Копии требуют явного переназначения; автоматического исторического реестра нет. Состояния упорядочиваются по явным stateId, pressed и feedback раздельны. Шрифты Figma px переводятся в Extron pt по явному правилу 72/96. Label ограничен LEFT/CENTER текущего донора; align-only различия состояний отклоняются согласно текущему независимому verifier.

По прямому сообщению пользователя у него есть лицензия Baolv/figma-export и разрешено использовать проект как основу. Закреплён commit `6312d15ea52470ab14600c49506f7f9e3c9aec91`. Адаптированы извлечение оформления, PNG, ZIP/download и UI/UX панели (fieldset/legend, компактные поля, основная кнопка, progress/status). Файл `src/figma-plugin/THIRD_PARTY_NOTICES.md` сохраняет происхождение и разрешение; текст лицензии не придуман. Delta, AI-синхронизация и localhost bridge не включены.

Зависимости и API зафиксированы lock-файлом; plugin API 1.0.0, typings 1.142.0, Figma documentAccess dynamic-page, сеть none. Используются только документированные get/setPluginData, чтение свойств, exportAsync и showUI. Экспорт не меняет назначения; переключение preview и сохранение metadata — отдельные явные действия. Async операции сериализованы, обязательный PNG не пропускается, изменения дизайна во время рендера прерывают экспорт.

Проверки разделены: Figma API fixture и выполнение собранного кода в VM; настоящий Chromium UI с смоделированным parent; настоящий .NET/x86 Extron путь на собственных копиях закреплённых доноров. Figma Desktop/реальные private metadata и PNG-рендер, новый GUI Designer-цикл и устройство не проверены. Схемы/ядро остаются прежними; импортируемая локальная сборка — MVP для этого следующего ручного шага. Протокол: `../verification/results/2026-10-19-figma-plugin.md`.
