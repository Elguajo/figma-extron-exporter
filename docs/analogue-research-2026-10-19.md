# Аналоги Figma → Extron: исследование 19 октября 2026

## Основной результат

Найден близкий технический аналог: [rob-paprocki/extron-gdl-toolkit](https://github.com/rob-paprocki/extron-gdl-toolkit). Он решает значительную часть задачи программного создания и изменения проектов Extron. Готового публичного продукта с полным маршрутом **Figma → редактируемый Extron GDL** в проведённом поиске не обнаружено.

Это уточняет прежний результат из `docs/research.md`: отсутствие найденного готового Figma-конвертера не означает отсутствия инструментов генерации GDL. Toolkit заслуживает отдельного воспроизводимого эксперимента до дальнейшей разработки собственного writer.

Проверены веб-поиск, поиск репозиториев GitHub, документация и отдельные исходные файлы кандидатов. Сторонние программы не устанавливались и не запускались; совместимость на нашем компьютере и оборудовании этим исследованием не доказана. План и решения на момент исследования не менялись. Последующий эксперимент описан в разделе «Воспроизведение у нас».

## Главный кандидат: extron-gdl-toolkit

### Состояние публичного проекта

По [GitHub API](https://api.github.com/repos/rob-paprocki/extron-gdl-toolkit) репозиторий создан 9 октября 2026 года. На дату исследования публичная ветка имеет один commit, звёзд и forks нет, [релизы отсутствуют](https://api.github.com/repos/rob-paprocki/extron-gdl-toolkit/releases). Автор объясняет короткую историю публикацией из отдельного частного архива; один публичный commit не говорит о длительности разработки.

Зафиксированный HEAD: `4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4`. Сведения ниже относятся к этому состоянию. В GitHub поле `license` равно `null`; в дереве нет общей LICENSE для toolkit. Отдельная лицензия Open Sans относится к шрифтам. Условия повторного использования кода ещё требуется выяснить. Позднее, 19.10.2026, пользователь сообщил о наличии лицензии (D010 в `decisions.md`); текст лицензии в репозиторий не передан.

### Что проверено чтением кода

- В [gdl/spec.py](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/gdl/spec.py) есть модель экрана, вычисление расположения элементов, назначение числовых ID, проверки и формирование плана. Есть таблица `TLP1025M` 1280×800 и `TLP300M`, для которого основной размер переопределён в 320×480. Это близко к нашим целевым панелям, но запись в таблице не доказывает аппаратную проверку.
- [examples/panel.json](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/examples/panel.json) показывает реальный контракт: страницы, подписи, кнопки, сетки, группы и ссылки на popup. Это конкретный образец для сравнения с нашим будущим `.exui`.
- [gdl/design.py](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/gdl/design.py) читает canvas Claude Design и преобразует его в описание панелей. Следовательно, перед генератором уже есть отдельный адаптер дизайна; Figma-адаптер теоретически может быть ещё одним входом. Это вывод по архитектуре, не существующая функция.
- [GdlProject.ps1](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/powershell/GdlProject.ps1) загружает EXE/DLL из установленного GUI Designer, десериализует граф через BinaryFormatter, клонирует объекты и записывает сериализованные поля через reflection. Независимого writer новых объектов здесь нет.
- [Apply-GdlPlan.ps1](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/powershell/Apply-GdlPlan.ps1) применяет план к проекту-донору, включая контролы и связи popup. Метод принципиально отличается от нашего ограниченного изменения строк без загрузки библиотек Extron.
- [gdl/container.py](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/gdl/container.py) читает контейнер и встроенный результат Build; умеет упаковывать `ProjectGCP` с дополнительной записью. В нём используется глобальная замена сигнатур KP/PK. Это проще нашего структурного reader; переносить реализацию без проверки на бинарных данных не следует.

### Что заявляет автор и что ограничивает применение

Автор указывает проверку на **GUI Designer 1.28.0.7**, совпадающем с нашей установленной версией. Это полезная точка для повторения опыта. По [описанию формата](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/docs/gdl-format.md) запись требует 32-битного Windows PowerShell 5.1 и установленного GUI Designer. Подход зависит от внутренних классов Extron и готовых объектов-доноров.

В [seeds/README.md](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/seeds/README.md) перечислены исходные проекты, включая TLP300M Portrait 320×480. Они распространяются через Git LFS. Там же отмечено, что модель результата определяется донором: одного изменения `model` в JSON недостаточно. Для TLP1025M необходимо подготовить или отдельно проверить правильный исходный проект.

[Roadmap автора](https://github.com/rob-paprocki/extron-gdl-toolkit/blob/4390741bd9acc6df7e9bbb4e5a9d9246ac7abdb4/docs/ROADMAP.md) прямо ограничивает доказательства:

- Загрузка созданного результата на физическую панель не зафиксирована.
- Большие сгенерированные интерфейсы ещё не проверены: упоминаются результаты до трёх страниц.
- Остаются вопросы шрифтов, прозрачности предпросмотра, ориентаций, горизонтальных слайдеров и полноты проверок.
- Часть эталонов и визуальных доказательств остаётся в частном архиве.

Таким образом, найден содержательный инструмент для разработчика с исходным кодом, а не подтверждённая готовая замена нашему продукту. Его автоматизация Build также выходит за нашу принятую границу: у нас экспортёр выдаёт редактируемый GDL, пользователь выполняет Build вручную.

## Что дают остальные кандидаты

**Официальный Extron.** На странице GUI Designer подтверждены шаблоны, библиотека элементов и Dynamic Scaling. В Mach перечислены обе наши модели — TLP Pro 1025M и TLP Pro 300M. Это полезный источник штатных проектов. Документированного импорта структуры Figma в рассмотренных материалах нет. Поисковый индекс прочитан; повторные прямые открытия части страниц Extron были заблокированы Bot Defense, скачивание комплектов не выполнялось.

**Extron-Frontend-API.** README требует заранее подготовить `.gdl` и подключить его к ControlScript. API позволяет менять страницы, подписи и состояния работающего интерфейса. Упомянутый `gui_element_instantiation_converter.py` помогает переносить объявления элементов из старого программного кода; это не генератор файла GUI Designer. Репозиторий имеет MIT-лицензию.

**UIUC.** [README](https://github.com/UIUCLibrary/UIUC_AV_StandardGUI_Extron_Public/blob/Main/README.md) описывает общий программный каркас и подключение готовых GUI. Он может помочь с именованием и организацией AV-интерфейса. Самостоятельного маршрута из Figma нет. Модули требуют xi-процессоры; переносимость на другие семейства не заявлена. Лицензия MIT.

**Baolv/figma-export.** [README](https://github.com/Baolv/figma-export/blob/main/README.md) описывает пакет JSON, ресурсов и превью, включая экспорт изменений. Это источник идей для входного пакета, но Extron-компоненты, постоянные AV-ключи и выходной GDL потребуется реализовать отдельно. Поле общей лицензии GitHub также `null`; полную проверку его кода не проводил.

**Figma to Qt.** [Официальная документация](https://doc.qt.io/figmatoqt/) подтверждает преобразование в QML, сопоставление с Qt Quick Controls, токены и предварительное выявление проблем. Для нашего проекта это пример устройства экспортёра, а не средство импорта в Extron. Переход на Qt потребовал бы другого целевого окружения.

## Рекомендация для проекта

До расширения независимого writer стоит провести ограниченный эксперимент с методом `extron-gdl-toolkit`: создать из небольшого описания редактируемый GDL с кнопкой «Музыка», подписью, громкостью и mute, затем вручную выполнить наш цикл проверки в GUI Designer. Повторить на правильных исходных проектах для 1280×800 и 320×480.

При успешном результате наиболее перспективным выглядит маршрут **подготовленные Figma-компоненты → наш пакет интерфейса → локальный адаптер к установленному Extron → GDL**. Это исследовательская рекомендация, не принятое архитектурное решение. Прямое включение чужого кода зависит от выяснения лицензии, а выбор метода — от воспроизводимой проверки.

Даже при использовании такого адаптера остаются собственные задачи: семантика AV-компонентов, постоянные ID между повторными экспортами, графика состояний, кириллица и шрифты, два разрешения панелей, понятные сообщения об ограничениях и интерфейс локальной программы. Наличие автоматического назначения ID в toolkit ещё не доказывает нашу гарантию сохранения ID при перестановке слоёв Figma.

## Границы поиска

Использованы веб-запросы `Figma Extron GUI Designer export converter plugin`, `Extron gdl parser github`, `Extron GUI Designer converter`, точные сочетания `Figma` / `Extron`, а также GitHub repository search: `extron figma`, `extron gui`, `extron gdl`, `extron converter`, `extron generator`, `figma extron in:readme`.

Поиск `extron gdl` вернул toolkit; общий поиск по `gdl` даёт много нерелевантных проектов Archicad. `severodaniel/extron-gui-designer` оказался пустым репозиторием, содержательной реализации для изучения не найдено. Одноимённый `Elguajo/figma-extron-exporter` также пришёл в выдаче с размером 0 и не посчитан независимым аналогом. Совпадение расширения `.gui` у CommandFusion не является свидетельством совместимости с Extron.

Поиск не был полным аудитом всех GitHub-файлов, закрытых форумов или партнёрских решений. Формулировка «готовый Figma → Extron не найден» относится к проверенным публичным источникам на указанную дату.

## Воспроизведение у нас (19.10.2026)

Исходники toolkit на `4390741` прочитаны в отдельной копии без Git LFS и не запускались. Приёмы реализованы заново (`src/adapter`) и проверены на нашей установке GUI Designer 1.28.0.7.

Воспроизведено:
- x86 Windows PowerShell 5.1 загружает 40 сборок GUI Designer и десериализует проект;
- клонирование и запись backing fields создают страницу, кнопки, подпись, Level и PNG-ресурс;
- `PBPlatformPro.CreatePlatform` даёт TLP1025M с part number 60-1566-02 и 1280×800;
- сохранение печатает безвредное «The system cannot find the file specified»;
- повторный прогон даёт побайтово тот же результат.

Позднее подтверждено вручную: результаты для TLP Pro 1025M и 300M открылись, редактировались, прошли Verify и Save and Build и открылись повторно. Работа на панели не проверялась.

Не воспроизводилось поведение конструкторов без UI.

Подробности и таблица «заявление → результат»: `../verification/results/2026-10-19-first-screen.md`.
