# Контракт `.exui`, версия 1

Несколько страниц, popup, группы и указание навигации добавлены отдельной версией 2: [exui-v2.md](exui-v2.md). Правила версии 1 ниже не изменились.

Кнопки Off/On без отдельного состояния удержания добавлены одностраничной [версией 3](exui-v3.md). В версии 1 по-прежнему обязательны три состояния.

Принят 19.10.2026 для одной страницы, уже проверенной экспериментом этапа 4. `.exui` — наш обычный ZIP, не формат Extron. Конвертация создаёт новый редактируемый `.gdl`. Build выполняет пользователь в GUI Designer.

## Состав и версии

```text
first-screen-1025m.exui
├── manifest.json
├── screen.json
└── assets/
    ├── note-dark.png
    └── note-light.png
```

`assets/` здесь обозначает префикс файлов; отдельной directory entry в ZIP нет. Имена регистрозависимы, только `/`. Разрешены ровно два JSON и объявленные PNG; лишние записи, дубли (в том числе различающиеся регистром), symlink, абсолютные пути, `..`, обратные слеши отклоняются. ZIP читается стандартной библиотекой .NET; имена из ZIP не используются для произвольной распаковки. Ресурсы копируются в приватную временную папку после проверки имён и удаляются после конвертации/отказа.

`manifest.json`: `schema: "exui/1"`, `profile`, `screen: "screen.json"`, `resources: [{path, sha256}]`. `screen.json`: `schema: "exui-screen/1"`, `project`, `page`, `assets`, `elements`. Оба маркера обязательны. Неизвестные версии и поля отклоняются, автоматического downgrade нет. Любое расширение принимаемого контракта требует новой согласованной версии и доказательств; исправление reader не должно менять смысл версии 1. Схемы не загружаются из пакета или сети.

Машиночитаемые JSON Schema 2020-12: [manifest](../schemas/exui-v1/manifest.schema.json), [screen](../schemas/exui-v1/screen.schema.json). Ключевые слова сверены с [официальной спецификацией JSON Schema](https://json-schema.org/draft/2020-12/json-schema-validation). В CLI встроены эти же файлы и ограниченный evaluator только используемых ими keywords; это не универсальная библиотека JSON Schema. Схемы проверяют форму; межобъектные ограничения ниже проверяет reader и существующий `ScreenSpecReader`.

JSON — UTF-8 без BOM, comments, trailing commas и повторных свойств; глубина до 32. Обязательные поля нельзя заменять `null`, кроме `label.controlId`. ZIP до 20 MiB, до 18 файлов, сумма распакованных файлов до 16 MiB; manifest до 64 KiB, screen до 256 KiB, до 16 ресурсов по 4 MiB. Проверяются фактические длины, ZIP CRC и SHA-256 ресурсов. SHA обеспечивает целостность, а не подлинность/доверие к автору.

## Профили и модель

| profile | Панель | Холст | Локальный donor id |
|---|---|---|---|
| `tlp-pro-1025m` | TLP Pro 1025M | 1280×800 | `tlp-pro-1025m` |
| `tlp-pro-300m-portrait` | TLP Pro 300M | 320×480 | `tlp-pro-300m-portrait` |

Один пакет содержит один профиль и одну страницу. Масштабирования и выбора другого профиля при конвертации нет. Для второй панели нужен отдельный пакет со своей геометрией и теми же семантическими ключами/ID. Прочитанный профиль реального закреплённого донора сверяется с пакетом. Пути к донорам, DLL, PowerShell или реестру пакет задавать не может.

`project.name` — имя проекта. `page` задаёт `key`, `objectId`, `name`, `background`. Холст задаёт профиль; страница становится стартовой. Сохраняется Offline popup донора; пользовательские popup и переходы не создаются. Preview, ресурсы, палитра и служебные данные донора остаются согласно ограничениям этапа 4.

`elements` — 1..64 элемента. `rect` — целые `[left, top, width, height]` в пикселях; положительные размеры, весь прямоугольник внутри холста. Массив определяет порядок коллекции controls, он передаётся без сортировки. Это не источник ID. Наложение и интерактивное поведение перекрывающихся элементов отдельно в GUI не проверены. Все элементы обычные видимые, динамическая видимость не описывается.

Общие поля: `kind`, `key`, `objectId`, `controlId`, `name`, `rect`. Текстовые поля — непустые строки до 256 UTF-16 code units, без NUL и повреждённого Unicode. Цвета — непрозрачный `#RRGGBB`. Шрифт у label/button обязателен: `family: "Arial"`, размер в пунктах 4..200, `bold: true|false`; семейство берётся из ресурсов донора. Это диапазон допустимых значений, качество каждого размера на устройстве не доказано.

| kind | Обязательные дополнительные поля | Результат |
|---|---|---|
| `button` | `font`, `states`, `press` | PBButton; текст в состояниях |
| `label` | `text`, `textColor`, `font` | PBLabel, `controlId: null` |
| `level` | `display: "slider"`, `orientation: "left-to-right"`, `min: 0`, `max: 100`, `fillColor` | PBLevel в режиме Slider |

Поля другого kind запрещены. Gauge, другие ориентации/диапазоны, PBSlider, отдельный image control, несколько страниц, группы, навигация, прозрачность, formatted text и динамический текст пока не входят в версию 1. Строки статичны при генерации; ID кнопки/Level — только адрес, без программирования поведения. Неподдерживаемое оформление отклоняется. Автоматическая растеризация запрещена: можно заранее подготовить собственный PNG и использовать его только как иконку состояния, сохранив кнопку редактируемой.

## Идентификаторы

- `key` — семантическая идентичность, lowercase сегменты через `.` или `-`, до 100 символов, уникален между страницей, элементами и ресурсами. У страницы/элементов сохраняется в Comments как `exui-key=<key>`; у ресурса служит ключом ссылок внутри пакета.
- `page.objectId` — 1..65534, ID страницы редактора; одновременно используется как start-page/userId страницы. 65535 зарезервирован Offline.
- `element.objectId` — 1..1000000, ID объекта редактора, уникален среди controls страницы. Пространство ID страницы отдельно.
- `controlId` — Extron UInt16 ID 1..65535 для button/level, уникален в пакете; у label явно `null`, записывается 0. Это не objectId и не номер Figma node.

Producer ведёт соответствие `key → objectId, controlId` в редактируемом исходнике. ID задаются явно; reader никогда не назначает их по позиции, тексту, имени или координатам. Копия элемента получает новый key и новые ID; удалённые значения producer не должен переиспользовать для другого назначения. Версия 1 не содержит исторического реестра/tombstones и не может обнаружить переиспользование между разными пакетами; такая автоматизация остаётся этапом 6. ID не обещают сохранение ручных изменений `.gdl`: повторная конвертация создаёт новый файл целиком; merge отсутствует.

## Состояния и ресурсы

У каждой кнопки ровно три состояния:

| stateId | role | Смысл |
|---|---|---|
| 0 | `normal` | Начальный вид |
| 1 | `feedback` | Вид, выбираемый внешней программой управления |
| 2 | `pressed` | Вид, пока кнопку держат; press feedback |

Каждое содержит явные `stateId`, `role`, уникальное внутри кнопки `name`, `text`, `fill`, `textColor`. Порядок записей JSON произволен: перед существующим генератором они сортируются по явному `stateId`; `idField/indexField` остаются 0/1/2. `press` обязан ссылаться на имя роли pressed. Имена могут меняться, явные stateId сохраняются. Все три вида должны различаться. Feedback не становится выбранным источником или mute автоматически: для этого нужна программа управления; команд, драйверов и AV-логики нет.

Необязательные `image` (семантический ключ asset), `imageAlign` (`top-center`/`middle-center`) и `textAlign` (`bottom-center`/`middle-center`); по умолчанию оба `middle-center`. Изображение используется в Native layout. Остальные варианты не заявлены контрактом версии 1.

`assets` задаёт `{key, file, resourceName}`. `file` — `assets/<lowercase letters/digits/hyphens>.png` (имя до 64 символов без расширения), путь точно совпадает с manifest. Каждый ресурс объявлен один раз, реально присутствует и использован состоянием. `resourceName` — уникальное без учёта регистра ASCII-имя `.png` до 100 символов; конфликт с донором выявляется адаптером. PNG до 4096×4096; reader проверяет signature, IHDR, длины и CRC chunks, IDAT и IEND. Это структурная проверка, полное декодирование изображения выполняет Extron/System.Drawing в адаптере. Чужие шрифты, SVG, JPEG и DLL не упаковываются.

## CLI и результат

```powershell
& $dotnet run --project src/cli --no-build -- validate-package examples/exui-v1/first-screen-1025m.exui
& $dotnet run --project src/cli --no-build -- convert-package examples/exui-v1/first-screen-1025m.exui output/new-1025m.gdl
```

Первая команда проверяет пакет без Extron и доноров. Вторая требует локальные доноры из `samples/donors.json`, x86 PowerShell 5.1 и GUI Designer 1.28.0.7. Возможны `--registry` и `--extron-dir` как локальные CLI options. Папка назначения должна существовать. Существующий GDL или соседний report приводит к отказу. Выход публикуется после независимой проверки; штатные ошибки проверки/адаптера оставляют оба конечных файла отсутствующими. Два файла не составляют атомарную транзакцию при аварийном завершении процесса/ОС.

Отчёт `<output>.report.json` содержит контракт, профиль, SHA пакета и screen, SHA донора и результата, независимые проверки NRBF и вывод адаптера. `GuiDesignerVerified` и `HardwareVerified` для нового результата false. Наличие отчёта не означает ручную проверку. Пути в отчёте отражают локальный запуск; временные файлы не являются воспроизводимым артефактом.

Коды отказа: `package-zip`, `package-size`, `package-entry`, `package-entries`, `package-json`, `package-schema`, `package-profile`, `package-resource`, `package-integrity`, `package-image`, `package-state`; семантические ошибки экспериментальной модели — `spec`, ошибки адаптера остаются прежними. Выходные коды CLI: 0 — успех, 1 — отказ, 2 — неверные аргументы.

Примеры и воспроизведение: [examples/exui-v1](../examples/exui-v1/README.md). Доказательства: [протокол этапа 5](../verification/results/2026-10-19-exui-v1.md).
