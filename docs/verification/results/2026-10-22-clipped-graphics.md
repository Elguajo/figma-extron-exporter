# Clip content для растрового фона, плагин 0.6.6

22.10.2026. Исправлен отказ распознавания и экспорта частично выступающего растрового фона при включённом Clip content у экрана/popup. Работа выполнена в основном checkout, ветка main; предыдущие изменения PDF сохранены и дополнены.

## Поведение и причина

Раньше `graphicBounds` всегда использовал полный `absoluteBoundingBox`, после чего общий bounds-check отклонял фон 1280×998 при Y=-99 на экране 1280×800. PNG рендерится на изолированной копии и не наследует клиппинг исходного родителя.

Теперь для `graphic` (`image_`, `img_`, `logo_`) при `parent.clipsContent` пиксельная область пересекается с прямоугольником экрана/popup. Видимая область становится rect экспортируемой картинки и размером временного Frame для PNG; смещение исходной копии сохраняет масштаб и положение рисунка. Используется прежний путь изолированного рендера `exportPng`, включая finally-очистку. Исходные слои, metadata и ID не меняются при экспорте.

Клиппинг самой картинки продолжает обрезать её внутренние слои. Выход самого Frame за экран разрешается только при клиппинге родительского экрана/popup. Полностью невидимая графика остаётся bounds-ошибкой; нативные контролы и текстовые элементы сохраняют прежние проверки. Скругления экранного холста по-прежнему не переносятся.

Контракт Figma сверялся с установленными `@figma/plugin-typings` 1.142.0 и официальной документацией: [clipsContent и absoluteBoundingBox](https://developers.figma.com/docs/plugins/api/node-properties/#clipscontent). Новых внешних зависимостей и изменений EXUI/5 нет; совместимый CLI 0.6.3, plugin ID прежний.
