# PNG-экспорт скрытых состояний: 0.1.2 — 19.10.2026

## Наблюдение и причина

[Скриншот пользователя](2026-10-19-figma-png-export/user-figma-before.png) подтверждает работу выбора в 0.1.1: выбран Frame «Главная», кнопки активны, но экспорт остановлен на `icon.note-dark` сообщением о несовпадении Native размера PNG. Фактические размеры PNG старая ошибка не выводила; точный PNG от Figma не получен.

`icon.note-dark` находится в скрытом feedback Frame. Экспорт вызывался на исходной иконке внутри скрытых/clipping предков, без явного `useAbsoluteBounds`. Оба исходных PNG имеют 64×64, непрозрачный рисунок занимает x=10..52, y=4..56. [Документация ExportSettings](https://developers.figma.com/docs/plugins/api/ExportSettings/) задаёт `useAbsoluteBounds=true` для полных размеров узла независимо от пустого пространства/обрезки; по умолчанию false. Рендер скрытой ветки и обрезка прозрачных полей были непокрытыми предположениями старого тестового API. Какая именно комбинация дала неверный размер у пользователя, до получения реального PNG не установлено.

## Исправление

Каждая иконка клонируется, временно переносится непосредственно на страницу за правую границу существующих объектов и делается видимой. Экспорт: PNG, SCALE 1, `useAbsoluteBounds=true`, `contentsOnly=true`. Исходный узел не переносится, видимость его предков не переключается. Временная копия удаляется в finally, включая отказ рендера. Проверка размера остаётся строгой и сообщает полученные/ожидаемые размеры; неподходящий PNG не принимается. `clipsContent` добавлен в снимок свойств для обнаружения правок во время асинхронного экспорта.

Пакет `.exui/1`, роли normal/feedback/pressed, semantic key, objectId/controlId, private metadata и plugin ID не менялись. Это исправление пути PNG для существующего демо; возможности формата не расширены.
