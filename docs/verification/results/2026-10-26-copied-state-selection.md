# Повторный выбор кнопки после сохранения ID — 26.10.2026

## Воспроизведение и причина

В тесте настоящего bundled command handler: назначенная кнопка скопирована, оригинал удалён, для новой кнопки сохранён Control ID 1. При повторном выборе интерфейс показывал `Off: это копия…`, хотя сама кнопка уже имела собственный ownerNodeId и сохранённый ID 1. Причина — строгое чтение назначений дочерних состояний в publish(). «Сохранить ID» намеренно меняет только выбранный элемент; назначения его скопированных состояний исправляются при проверке/экспорте. Это сообщение не означало потерю сохранённого ID кнопки.

## Изменение

Чтение списка состояний и переключение предпросмотра допускают унаследованные назначения. Это операции чтения/видимости: metadata и ID не переписываются. Проверка повреждённых metadata, неоднозначного состояния, владения и конфликтов при экспорте сохранена.

Дополнительно проверены ручные ID 1/2: неправильное размещение, перемещение между popup, перестановка слоёв, ошибка роли состояния, перезапуск и экспорт. ID сохраняются. Отдельно подтверждено прежнее поведение: пересозданная кнопка с новым Figma node ID и унаследованным ownerNodeId получает новые предлагаемые ID как копия; явное «Сохранить ID» закрепляет выбранный номер. История изменений пользовательского макета недоступна, поэтому точную причину его прежнего переназначения по скриншотам установить нельзя.
