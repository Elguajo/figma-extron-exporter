# Оформление выбранных popup — обновление 0.7.0, 23.10.2026

## Причина и воспроизведение

В `ExportScope.resolveButtons()` выделенный popup или группа рассматривались только в режиме `selection`. При восстановленном `selected-frames` или `page` команда использовала проект экспорта и обновляла его готовые кнопки вместо выделенного popup. Получалось сообщение «Кнопок: 29; новых состояний: 0», хотя кнопки выделенной группы оставались без состояний.

Регрессионный сценарий: экран с 29 готовыми кнопками, отдельная выделенная `popupgroup_WallLayouts`, внутри `popup_WallFull` с обычной Group-кнопкой и кнопкой с единственным Normal. До исправления четыре варианта (оба режима проекта, с назначениями и по префиксам) падали на проверке области: плагин возвращал ID проекта вместо ID выделенной группы.

## Изменения

- Выделенный Frame popup, модального окна, группы или popup выбранного дочернего слоя задаёт локальную область оформления независимо от режима экспорта.
- Режим, сохранённые участники проекта, геометрия, ID и кнопки постороннего экрана сохраняются.
- Результат называет обработанную область, отдельно считает подготовленные и обновлённые кнопки и созданные состояния. При нуле обработанных кнопок указано «Изменений нет».
- `modalpopup_SourceSelect` проверен со смесью неподготовленной кнопки с Group 17, готовой Off/On с видимым On и ручной Normal/Pressed. Есть варианты выбора Frame/дочернего слоя, пропуска/обновления готовых и всех трёх режимов экспорта.
- Версия по запросу пользователя сохранена **0.7.0**, совместимый CLI **0.7.0**; EXUI/5 и metadata не менялись.
