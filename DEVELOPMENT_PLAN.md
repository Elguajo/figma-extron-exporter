## 1. Цель и архитектура

Создать инструмент, который переносит подготовленный интерфейс из Figma в редактируемый проект Extron GUI Designer.

```text
Figma
  ↓ плагин экспорта
Пакет интерфейса .exui
  ↓ локальная программа Windows
Редактируемый проект .gdl
  ↓ открытие, Verify, Save and Build
GUI Designer
  ↓ подключение логики программистом
AV-система
```

`.exui` — предлагаемое расширение нашего ZIP-пакета, а не существующий стандарт Figma или Extron. Минимальная версия 1 зафиксирована в `docs/exui-v1.md` и `schemas/exui-v1`.

Figma отвечает за оформление, компоновку и описание состояний. Локальная программа отвечает за проверку пакета, сопоставление элементов, сохранение идентификаторов и генерацию проекта. GUI Designer остаётся средой финальной проверки и штатной сборки.

Локальная программа не должна становиться вторым полноценным редактором дизайна. Её результат — редактируемый `.gdl`; функцию Build в экспортёр не добавляем. Пользователь выполняет Build внутри GUI Designer. Штатная сборка в исследовательских протоколах нужна только для проверки совместимости. Управление оборудованием, драйверы, DSP-маршрутизация и подтверждение реальных состояний выполняются отдельной программой управления Extron.

Главный технический риск: корректная генерация `.gdl`. Перенос генератора из Figma в Windows расширяет выбор инструментов, но сам по себе не решает этот риск.

## 3. Технологические решения

- Figma-плагин: TypeScript с компиляцией в JavaScript.
- Промежуточный пакет: ZIP, JSON и графические ресурсы; явная версия схемы.
- Локальная программа: Windows; C#/.NET — основной кандидат. Окончательный выбор среды выполнения и библиотек принимается после прототипа записи `.gdl`.
- Сначала разрабатывается консольный конвертер; графическая оболочка добавляется после доказательства экспорта.
- Ядро преобразования не зависит от графической оболочки и API Figma.
- Внутренние библиотеки Extron экспериментально используются для этапа 4 через отдельный x86-процесс (D006). Это не публичный SDK. Ядро от них не зависит. Их распространение с нашей программой не предполагается.
- В первой версии поддерживается ограниченный набор AV-компонентов. Произвольный макет Figma не должен автоматически распознаваться как работающий интерфейс.

## 6. Обязательные правила качества

1. Не считать расширение `.gdl` или успешную распаковку доказательством совместимости.
2. Отличать проверку контейнера, открытие редактором, успешную сборку и реальную работу на панели.
3. Не менять ID из-за порядка слоёв или косметических правок.
4. Не обещать автоматическое сохранение ручных правок программиста без проверенного механизма обновления.
5. Сохранять исходные образцы неизменными; каждый эксперимент выполнять на копии.
6. Подтверждать поддержку версии GUI Designer отдельным прогоном эталонов.
7. Не подменять неизвестную логику AV-системы вымышленными маршрутами и состояниями.
8. Не тратить время на полный desktop UI и плагин до доказательства этапа 4.

## 7. Ближайшая работа

Пересобранная копия и программное изменение подписи кнопки Start (ID 8000) на «Музыка» прошли штатный цикл GUI Designer. В исходном проекте checksum имеет тип UInt64 и равен 0; ненулевые значения редактор текста отклоняет. Многозаписный контейнер после Save and Build теперь читается.

Собственный экран генерируется через локальный адаптер (D006) для обоих профилей. Он проходит независимую проверку данных и ручной цикл GUI Designer: открытие → редактирование → Verify → Save and Build → повторное открытие. Контрольный рубеж этапа 4 достигнут на уровне GUI Designer; работа на панели не проверена.

Следующие шаги:
- проверить панель или Extron Control с процессором, когда будет доступ к системе Trilliant;
- продолжить этап 6: исторический реестр ID, копирование/удаление, отчёт изменений; расширять контракт только после отдельных проверок;
- Figma-плагин и desktop UI остаются следующими самостоятельными этапами, в текущую работу не входят.

Открытые вопросы: эталоны из Create Wizard (особенно 1025M) и условия использования внутренних классов Extron.

Этапы 1–3 остаются частично выполненными. Build остаётся действием пользователя внутри GUI Designer и не автоматизируется.

Сроки полной разработки оценивать после этапа 4: до него основная неопределённость лежит в формате Extron. Этот план задаёт порядок работ, но не фиксирует неподтверждённую дату завершения.
